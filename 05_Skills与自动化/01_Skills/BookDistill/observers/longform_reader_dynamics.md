# Observer: Longform Reader Dynamics v0.1

> observer_id: `longform_reader_dynamics`

## 作用

直接阅读原著，研究“这部长篇怎样持续运转、怎样持续调度读者”。

它不是剧情摘要器。目标是同时看见：

- 发生了什么；
- 人物为什么继续行动；
- 读者此刻被要求期待、担心、猜测或等待什么；
- 这些东西怎样跨章累积、兑现、转向。

## 阅读纪律

### 1. 直接读原著

按 SourcePrepare 的稳定章节顺序阅读 `chapters/NNNN.md`。

允许分章、分块、多个子 Agent；但每个结论的事实依据必须回到原文章节，而不是只引用前序摘要。

### 2. 逐章维护六类状态

每章优先追踪：

1. **人物驱动**
   - 当前欲望 / 局部目标；
   - 阻力；
   - 关键选择；
   - 选择的代价/后果；
   - 本章结束后目标或处境怎样变化。

2. **Reader Promise / 责任账本**
   - 新建立了什么期待或问题；
   - 哪些旧期待被部分兑现；
   - 哪些重大承诺被兑现；
   - 哪些问题被延迟；
   - 延迟后是否增加了新信息/新代价，而不是原地拖延。

3. **信息状态**
   - 角色知道什么；
   - 读者知道什么；
   - 谁比谁多知道；
   - 本章新增、确认、推翻、误导了什么；
   - reveal 的时机如何改变意义。

4. **情绪生态**
   - 压力如何上升；
   - 哪里释放；
   - 哪里换气；
   - 情绪是否连续同质化；
   - 某个低强度段落是否在为后续高强度制造对比。

5. **关系运动**
   - 信任、欲望、权力、距离、误解、依赖发生了什么净变化；
   - 关系变化是否由事件/选择触发，而不是作者说明。

6. **前进动力**
   - 本章/场景的功能；
   - 章末留下的 forward pull；
   - 读者继续读是为了事件结果、人物选择、关系、谜题、情绪回报还是其他东西。

### 3. 逐章观察不等于机械表格

不是每章都要六项齐全。

如果一章主要靠氛围、人物相处或生活感维持读者，它仍可能在“情绪生态 / 关系运动 / Reader Promise”上有高价值，不要因为没有大事件判定为低信息章。

### 4. 重点寻找“扩写过程”

借鉴 oh-story 的“关键信息与扩写技法”思路，区分：

`本章必须让读者得到的核心信息`
与
`作者怎样把这条信息扩成可读场景`

观察可以包括：

- 延迟揭示；
- 反应层放大；
- 信息差；
- 对比锚点；
- 身体反应；
- 小目标嵌套；
- 误导与回扣；
- 对话/事件/细节如何共同承载一条信息。

不要直接把上游的套路词表当成真理。发现不在词表里的有效方法，照常记录。

## 跨章综合

完成若干章节后，在 `synthesis.md` 做窗口级/全书级聚合。

至少检查：

### 作品发动机
- 什么东西让故事能持续数十/数百章；
- 核心目标是否变化；
- 每个阶段靠什么刷新冲突和回报。

### Promise / Payoff
- 大承诺、小承诺、关系承诺、谜题承诺如何交错；
- 延迟多久；
- 兑现方式是否改变旧信息的意义；
- 是否存在“旧债未还却不断开新债”。

### 情绪曲线
- 高压/低压如何交替；
- 生活感、幽默、暧昧、温情等是否承担换气功能；
- 大高潮前后有没有足够对比。

### 信息债与 Reveal
- 谜题怎样被命名但不解释；
- 哪些线索先作为异常存在；
- 真相揭示前读者拥有哪些可用模型；
- 真相后旧场景是否被重新解释。

### 剧情单元
可参考 oh-story 的剧情单元聚合，但不要机械按固定数量切分。
每个单元应至少具有：相对独立目标、主要冲突、阶段转折、净变化。

### 跨尺度效果链
重点寻找：
`一句/动作/细节 → 场景读感 → 多章期待 → 后续兑现`
这种单点分析看不到的组合效果。

## 输出要求

每章只把值得后续核证的条目写入 observer staging。

推荐 dimension：

- `长篇运行`
- `Reader Promise`
- `信息控制`
- `情绪`
- `关系`
- `节奏`
- `Scene Turn`
- `结构`
- 其他真实需要的开放维度

示例格式：

```text
- [OBSERVATION] dimension:信息控制 | observer:longform_reader_dynamics | 先让异常造成实际后果，再延迟解释机制，使问题从“这是什么”升级为“它会造成什么代价”｜证据：chapters/0012.md#L40-L67｜置信度：高
```

不要在这里写：

“因此所有悬疑小说都应该先展示后果。”

这类跨作品结论不属于单书观察者。

## 什么时候提出 Deep Dive

只有出现以下情况之一：

- 某个能力明显是本书核心强项，但当前观察解释不够；
- 两种解释都能解释证据，结论会影响 BKP；
- 某个效果跨很多章节，普通逐章记录无法解释；
- BookProfile 与实际阅读发生明显冲突；
- 有重要但暂时无法命名的效果链。

提出问题，不预设答案。由 BookDistill 决定是否进入 Apodictic 式专项深挖。
