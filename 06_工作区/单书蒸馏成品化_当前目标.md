# 单书蒸馏成品化｜当前目标

> 当前主线：把已有 SourcePrepare + BookDistill 收成“一本书一次交给 Agent”的可用流程。

## 用户侧目标

用户只做一次操作：指定一本书并要求“蒸馏这本书”。

Agent 内部自动完成：

1. 检查/运行 SourcePrepare，得到 PASS 标准输入；
2. BookDistill Base Scan；
3. 两个互补 Discovery Pass：长篇运行/读者动力、Reader/Page Craft；
4. 生成 BookProfile，据此决定是否需要 0～N 个专项 Deep Dive；
5. 总编辑式回源核证、合并、补 scope/boundary/confidence；
6. Finalize BKP；
7. 校验并确认 KnowledgeRetrieve 可以发现该 BKP。

## “蒸馏几次”的定义

对用户来说：**一次蒸馏任务。**

对内部分析来说：

- Base Scan：1 类基础扫描；
- Discovery：至少 2 个互补观察 Pass；
- Deep Dive：0～N，按作品真实强项/疑点自适应，不固定数量；
- Finalize：1 次总编辑收敛。

这不是要求把整本书完整塞给模型固定读取若干遍。长书可按章节/分块执行，同一 Pass 的中间结果写入文件，再跨章收敛。

《一九八四》《三体》验证时各做过 3 次专项 Deep Dive，只证明流程可运行，不代表以后每本书固定蒸馏 3 次。

## 最终用户得到什么

作者默认只需要看到：

- BookProfile：这本书擅长什么、有哪些值得调用的创作问题、哪些地方不确定；
- BKP：未来写作时由系统检索调用的长期知识包。

BKP 内部保存作品地图、Observation、重要 Inference、Work-specific Pattern、专项 Deep Dive 结果及证据/边界/置信度。

逐章 evidence、manifest、报告、Agent 工作记录主要用于审计和返查，不要求作者日常阅读。

## 当前开发任务

不是继续增加分析理论，而是做一个**单书编排入口**：

`书名/book_id → SourcePrepare（如需）→ BookDistill 多 Pass → 自适应 Deep Dive → BKP Finalize → Retrieval 可发现 → 最终简短报告`

优先复用已有 SourcePrepare / BookDistill 脚本和协议，只补编排、状态判断、失败报告和必要的恢复能力。

完成标准：选一部尚未蒸馏的新书，用户只发一次指令，Agent 能独立跑到最终 BKP；除真实 REVIEW/FAIL/重大文学判断冲突外，不要求用户中途操作。
