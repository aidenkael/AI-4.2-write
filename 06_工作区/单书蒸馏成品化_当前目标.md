# 单书蒸馏成品化｜当前目标

> 当前主线：把已有 SourcePrepare + BookDistill 收成“一本书一次交给 Agent”的可用流程。

## 用户侧目标

用户只做一次操作：指定一本书并要求“完整蒸馏这本书”。

Agent 内部自动完成：

1. 检查/运行 SourcePrepare，得到 PASS 标准输入；
2. Discovery A：长篇运行/读者动力；
3. Discovery B：Reader/Page Craft；
4. 生成 BookProfile；
5. 据此决定默认 0–2 个专项 Deep Dive；
6. 总编辑式回源核证、合并、补 scope/boundary/counterevidence/confidence；
7. Finalize BKP；
8. 校验 KnowledgeRetrieve 可以发现并召回该 BKP。

除真实 `REVIEW/FAIL`、作品身份冲突或重大不可裁决解释外，不要求用户中途操作。

## “蒸馏几次”的统一定义

对用户来说：**1 次蒸馏任务。**

对内部文学分析来说：

- **2 次全书蒸馏**：Discovery A + Discovery B；
- Base Scan 的 MAP/FACT/INFERENCE/OBSERVATION/BOUNDARY 是两次阅读中的证据记录层，**不另算第三次全书蒸馏**；
- BookProfile 是导航与专项路由，不算一次蒸馏；
- **默认 0–2 次局部 Deep Dive**：只看相关章节/主题，不重新无差别扫描全书；确有明显额外价值时可以超过 2 个，但必须说明原因；
- **1 次最终总编辑收敛**：综合、回源核证和封装，不算第三次全书蒸馏。

因此统一回答：

> **1 次用户操作 → 2 次全书蒸馏 → 默认 0–2 次局部深挖 → 1 次最终收敛 → 1 个正式 BKP。**

“一个 Pass”是分析目标，不等于单次模型调用。长书可按章节/稳定分块执行，中间结果写入文件后再跨章收敛。

## 两次默认全书蒸馏各看什么

### Discovery A｜长篇运行 / 读者动力

优先借 oh-story + AI-Novel-Writing-Assistant：

- 故事发动机、长篇推进与阶段变化；
- reader promise / controlling idea；
- 章节/场景功能；
- 即时欲望、阻力、选择；
- 期待建立、延迟、兑现；
- 情绪生态、压力/释放；
- 信息债、悬念、reveal timing；
- 人物与关系推进；
- 跨章/跨卷回收和追读动力。

### Discovery B｜Reader / Page Craft

优先借 creative-writing-skills：

- 逐时读感、疑问、预测、投入/漂移；
- 人物心智可信度；
- POV、叙事距离、声音；
- 句法、节奏、意象；
- 对话、潜台词、动作、感官、心理距离；
- 留白、幽默、暧昧、欲望、尴尬、惊奇；
- 微观机巧、组合效果与难命名价值。

两个 Pass 必须真正互补，不允许把同一份摘要换口吻复述。

## Deep Dive 怎么决定

前两次 Discovery 完成后由 BookProfile 路由。

默认 0–2 个专项，优先借 Apodictic 等成熟分析镜头，例如：contract、Reader Experience、Decision Pressure、Scene Turn、Emotional Craft、Reveal Economy、Character Architecture、POV/Voice、Theme。

没有真实高价值缺口就 0 个，不为流程完整强行深挖。

## 最终用户得到什么

作者默认只需要看到：

- **BookProfile**：这本书擅长什么、哪些创作问题值得调用、哪些地方仍不确定；
- **BKP**：未来写作时由系统检索调用的长期知识包；
- **简短完成报告**：SourcePrepare 状态、两次 Discovery 覆盖、Deep Dive 数量/主题、BKP 路径、Retrieval 是否可用、唯一未解决问题（如有）。

BKP 内部保存作品身份、作品地图、Observation、重要 Inference、Work-specific Pattern、专项 Deep Dive 结果及 Evidence/scope/boundary/counterevidence/confidence。

逐章 evidence、manifest、Agent 工作记录主要用于后台审计和恢复，不要求作者日常阅读。

正常写作阶段只检索 BKP，不重新蒸馏原著。

## 当前开发任务

不是继续增加分析理论，而是做一个**单书编排入口**：

`书名/book_id → SourcePrepare（如需） → Discovery A → Discovery B → BookProfile → 默认 0–2 个按需 Deep Dive → Finalize → Retrieval smoke test → 最终简短报告`

优先直接借成熟实现：

- oh-story：单一深度管道、章节边界单一真值、逐章处理、`_progress` 断点恢复、聚合；
- AI-Novel-Writing-Assistant：范围定向、token 预算、分档/增量深度扫描、证据回溯；
- creative-writing-skills：Discovery B；
- Apodictic：专项 Deep Dive；
- ani-book-skill：evidence-first、权威工件、确定性校验、可恢复状态。

优先复用已有 SourcePrepare / BookDistill 脚本，只补编排、阶段状态、断点恢复、失败报告、Deep Dive 路由和 Retrieval 登记。

## 完成标准

选一部尚未蒸馏的新书，用户只发一次“完整蒸馏这本书”的指令，Agent 能独立跑到最终 BKP；中断后可恢复，完成的章节/Pass 不重复处理，最终 BKP 可被 KnowledgeRetrieve 发现并召回。
