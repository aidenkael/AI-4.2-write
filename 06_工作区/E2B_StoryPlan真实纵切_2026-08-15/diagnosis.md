# E2-B｜P0_FREE_PLAN 真实弱点诊断

> 输入仅为已冻结的 `P0_FREE_PLAN.md`。
> 本诊断发生在任何 KnowledgeRetrieve / BKP 注入之前。
> 目的不是把 P0 改成“更专业的大纲”，而是确认它是否真的暴露了值得后续处理的问题。

## 先判断 P0 已经成立的部分

### 1. 长篇发动机基本成立

P0 没有靠“再来一个更大的事故”推进。旧路退出日常运输体系后，姐妹的两套能力——宋宁的地方末端关系与宋乔的区域运力/标准化体系——既互补又排斥。合作越成功，未来必须选哪种生存方式的问题反而越清楚。

这使故事可以自然产生后续，而不是依赖不断升级事件规模。

### 2. 第一次不可逆伤害来自人物主动选择

前半程终点不是事故、阴谋或误会，而是宋宁在现实期限下主动签下“共同保量”的客户承诺。这个选择既保住她继续独立经营的可能，又真实抽走宋乔竞标方案需要的货量。

它同时具备：

- 宋宁有充分现实理由；
- 宋乔受到真实而非象征性的损害；
- 选择不能靠姐妹私下和解轻易撤销；
- 宋宁自己也承担新风险。

因此冲突没有被简化成正邪。

### 3. reader promise 在主要商业线中有持续兑现

“地方运输生态正在消失”不是背景说明，而是通过限行、客户选择、末端网络、调度能力、融资、未来中转结构等逐渐改变人物选择。

人物关系也不是单独的一条家庭戏：双方越理解对方的专业判断，就越难简单否定对方，同时越明确双方利益无法完全兼容。

### 4. deliberate ambiguity 保留良好

五个作者未决项没有被当成事实回答。尤其旧债只出现“现实后果”和“解释冲突”，没有确定用途；宋乔的某些反应只允许产生多重解释，没有被升级成“她其实知道真相”。

当前未发现 `ILLEGALLY_FIXED`。

# 冻结两个真实弱点

只保留两个，不继续扩写问题清单。

## W1｜推进过于整齐，存在轻度“策划委员会感”

P0 的因果是成立的，但排列得过于顺手：

临时运输困难
→ 姐妹合作成功
→ 信息共享产生边界问题
→ 旧债制造资金困难
→ 宋乔提出并入方案
→ 客户分化
→ 竞标期限逼近
→ 宋宁签保量协议。

每一段都恰好承担一个结构功能，而且几乎每次合作都被规划成“现实问题解决 + 关系矛盾加深”的双重推进。

这种设计在概要层面清楚，但真正进入长篇后可能产生两个风险：

1. 地方物流生态中的其他人像被安排来证明姐妹的冲突，而不是拥有自己的迟疑、算计、惯性和不一致；
2. 读者可能过早感到每个现实问题都会准时转化为下一枚剧情齿轮，生活本身的偶然、拖延、无效劳动和局部反复不足。

这是一个真实弱点，但目前看更像**基础模型第二轮自由修订就可能改善的问题**，未必需要 BKP。

## W2｜父亲旧债仍然“可拆除”，尚未真正成为关系发动机

P0 明确遵守了“不把旧债做成单纯谜底”的要求，也让债务产生了两个现实作用：

- 宋宁的过渡融资更困难；
- 姐妹对旧账的解释发生冲突。

但如果把“父亲旧债”从 P0 中拿掉，主商业线几乎仍然可以完整成立：

旧路关闭 → 联运合作 → 客户分化 → 姐妹提出不同未来方案 → 竞标与客户期限 → 宋宁签保量协议。

也就是说，旧债目前更多是一个额外压力源和悬而未决的背景，而不是一个持续改变姐妹当前选择结构的变量。

这与冻结 reader promise 中的要求仍有距离：

> 家庭旧债不是单纯谜底，而要持续改变她们今天的关系和利益。

真正需要补的不是更多“神秘线索”，也不是更早揭露真相，而是：

**在不决定债务用途、不决定姐姐离开原因的情况下，让旧债反复迫使姐妹对同一现实资源、责任或风险作出不同选择，并让这些选择留下累积后果。**

例如理想的改进方向应关注“现在谁承担什么、谁因此失去什么、谁从对方行为中更新了什么判断”，而不是再增加一份旧账、一个神秘债主或一次追问真相。

W2 因此是本轮更适合测试知识介入价值的弱点。

# 主弱点冻结

`W* = W2`

原因：

- W2 直接命中当前 reader promise 的未充分兑现部分；
- 需要处理的是“未解过去如何持续改变现在”，不是简单润色；
- 处理失误很容易滑向谜题化、线索堆积或提前解释过去，因此存在明确方法边界；
- 相比 W1，它更可能存在可复用的写作知识，而不是只靠增加生活杂质即可解决。

## 给 KnowledgeRetrieve 的问题定义

后续 Retrieval 应围绕下述问题，而不是搜索“债务剧情怎么写”：

> 在不揭开旧债真相、不把过去秘密做成线索解谜链的前提下，怎样让一个未解决的过去事项通过人物当前的行为、选择成本、责任分配和关系判断持续产生累积后果？重点是让读者通过现在发生的事不断更新对人物关系的理解，而不是靠解释过去获得推进。

### Retrieval 使用门槛

- 0 张 BKP 完全合法；
- 如果召回内容只是泛泛的“秘密要分层揭示”“制造悬念”“逐步揭露”，应判定为 `NO_USEFUL_BKP`；
- 最多优先选择 1 张真正能改变 W2 修订方法的卡；
- BKP 只能用于挑战/补洞/深化，不能替换 P0 整体骨架。
