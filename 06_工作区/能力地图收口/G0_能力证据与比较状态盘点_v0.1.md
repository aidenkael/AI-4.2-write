- 不搜索新 GitHub 项目；不新建 Benchmark；不修改能力地图 v0.1。

### 1.2 证据分类模型（双轴）

本轮使用两个独立字段，不再用单一 A/B/C 字母同时表达"是否运行过"和"结论有多强"。

**字段一：实际执行状态**（描述"做了什么"）

| 状态 | 含义 | 典型场景 |
|------|------|---------|
| 正式实测 | 有冻结输入、正式运行/对照、结果记录，且可追溯 | B02 Round1（9 run）/ Round2A（12 run）；B09 Round01（24 run） |
| 轻量实测 | 做过真实任务或 Smoke Test，但不是完整正式 Benchmark | B09 Round02A（4 任务 × 2 条件） |
| 代码/架构审阅 | 读过代码、README、Skill、Prompt、工作流或架构，无真实任务效果比较 | 本地冻结后只读审阅 |
| 文档/行为观察 | 根据公开说明、已有报告或运行行为了解，无代码级证据 | 仅根据 README/文档 |
| 未实测 | 只有候选关系或问题意识 | 仅列入候选池 |

**字段二：结论证据强度**（描述"知道了多少"）

| 强度 | 含义 |
|------|------|
| 无效果证据 | 没有任何真实效果数据 |
| Exploratory | 有正式运行但存在方法学限制（样本过小、评审污染、无重复等），结论仅为探索级 |
| 方向性证据 | 有真实任务效果信号，作者有正向判断，但样本不足以构成统计结论 |
| M3 初步验证 | 至少一轮正式对照/盲测，有方向性证据，多方评审支持 |
| M4 跨样本验证 | 多任务、多样本、重复验证通过 |
| M5 生产固化 | 已在真实生产中持续使用并确认有效 |

**关键区分**："正式实测"不等于"强结论"。例如 B02 Round1 执行状态为正式实测，但因方法学限制（单 cell 单次运行、评审独立性受限），结论强度仅为 Exploratory。

**禁止**：把"出现在候选池""被讨论过""被 clone 过""被许可审计过""被列入能力地图"写成"已实测"。

**项目整体 vs 机制子集**：对每个上游项目，必须区分"项目整体是否直接运行"和"其机制子集是否进入正式 Runner"。一个项目整体未运行，不代表其机制没有实测。

### 1.3 成熟度标记（来自 v0.1，本轮不修改）

- M0 未研究 / M1 候选已知 / M2 协议可测 / M3 初步验证 / M4 跨样本验证 / M5 生产固化

### 1.4 许可证状态分类

| 标记 | 含义 |
|------|------|
| P1 | 当前私人研究可直接使用（MIT / Apache-2.0） |
| P2 | 当前私人研究可使用，但未来公开/商业化需复审（CC BY-NC-SA / AGPL） |
| P3 | 许可证/授权未完全核实，仅可研究公开思想/行为 |
