# E1｜StoryDesign 冻结结论：稀疏后置问题驱动的知识介入

> 状态：**FROZEN（E1-B / E1-C / E1-D 连续证据收敛）**。冻结日期：2026-08-15。
>
> 本文件是 E1 系列实验的正式结论入口；实验中间工件仍保留在本地 sandbox，不全量入库。

## 正式结论

**BKP_POSTHOC_SPARSE_PROBLEM_DRIVEN**

必须同时成立的边界：

- BKP 并非每次必要；0 张是正常路径；
- BKP 的独立增益目前只得到窄证据支持（E1-D 中 K016 对特定 W1 的小幅、可追溯增益）；
- 不得外推为“知识库越多越好”，也不得外推为“每个创作问题都值得检索”。

## 冻结的 StoryDesign 使用策略

1. 强模型优先自由完成第一轮原创设计。
2. 不默认在第一轮设计前注入 BKP。
3. 第一轮之后先诊断真实薄弱点。
4. 只有存在明确知识缺口时才调用 KnowledgeRetrieve。
5. BKP 默认允许 0 张。
6. 常规目标为 0–1 张；只有不同卡分别解决不同明确缺口时才允许更多。
7. KnowledgeRetrieve 返回 OK ≠ 必须使用知识卡。
8. 相关但没有独立增益的卡必须允许拒绝。
9. BKP 主要用于 challenge、counterexample、gap filling、targeted deepening、boundary checking。
10. BKP 不负责搭建第一版故事骨架。
11. 不默认生成分卷、多路线、风险清单、分层揭示、多时钟等固定策划形状。
12. 专业 stance / Agent 只在具体缺陷触发时使用，不默认全开。
13. 模型自身已经能解决的问题，不为了展示知识库价值重复注入 BKP。
14. `NO_USEFUL_BKP` / `INSUFFICIENT_BKP` 是正常结果，不是失败。
15. 作者可见结果优先保留人物、场景、关系和具体生活质感。
16. trace/provenance 继续完整保存工程信息，但不强迫作者阅读。

## 三轮实验的关键证据

### E1-B｜知识前置 A/B（2026-08-14）

三组种子、同模型同思考等级、A（裸模型）对 B（StoryDesign + 前置 3 张 BKP）。

- 结论：**前置较多知识会提高结构纪律，但可能损失人物自然度和生活质感。**
- B 稳定提供更显式的长篇发动机、阶段遗留后果与开放选择；但三组输出趋同于“分层揭示、阶段旧债、多方向、风险清单”的同一种语法。
- 三组真正专门的问题都存在知识缺口，应记录为 `NO_USEFUL_BKP`；排名较高但尺度越界的卡片被拒绝，没有为证明知识库价值硬塞。
- 证据入口：`E1B_StoryDesign_AB_验证_2026-08-14/internal_report.md`。

### E1-C｜稀疏后置 BKP 对照（2026-08-15）

单 Seed，B-current（知识前置）对 B-lite（自由初稿 → 窄诊断 → 后置检索 → 0–2 张选卡 → 定点修订），独立盲评后解盲。

- 结论：**“自由初稿 → 窄诊断 → 后置修订”优于当前知识前置策略，但尚不能把改善全部归因于 BKP。**
- B-lite 在检索前的自由初稿已拥有绝大多数人物生命感、生活细节与关系自然底色；后置链保存了这些材料并做了可见但有限的修订。
- B-lite 两个窄知识需求最终只选 1 张（K016），KN2 明确标记 `NO_USEFUL_BKP`。
- 证据入口：`E1C_StoryDesign_稀疏后置BKP_验证_2026-08-15/comparison/internal_comparison.md`。

### E1-D｜BKP 独立边际价值消融（2026-08-15）

固定同一自由初稿与同一 W1/W2 诊断，C0 不见任何 BKP，C1 只额外看冻结 K016，各自一次二次修订，双份独立盲评。

- 结论：**严格消融中 K016 对特定 W1 提供小幅、独立、可追溯增益**（跨情境职业动作与人物心智累积）；W2 保持 `NO_USEFUL_BKP`。
- 两份盲评在不知 K016 的情况下独立识别出该特征；事实性/程序性补强不可归因给 K016。
- 证据入口：`E1D_BKP独立边际价值消融_2026-08-15/technical_report.md`、`internal_attribution.md`。

## 证据强度与不做什么

- 这是窄证据：单 Seed（E1-C/D）、三组 A/B（E1-B）、单一 BKP 库（《长安十二时辰》48 卡）。
- 不宣布“BKP 普遍必需”，不外推为长期固定上限数字；0–1 张的常规目标需在后续真实 StoryDesign 调用中继续检验。
- 本冻结不修改 StoryDesign runtime 正式代码（现有 0 BKP / gap / noncanonical 路径已成立），只同步 Skill 使用策略、ADR 与长期原则。
