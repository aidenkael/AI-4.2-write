## 1. 当前创作问题

林昼在夜班发现一份标记为姐姐林晚的封存记忆；林晚官方已死亡三年，而该档案提交日期晚于死亡日期六个月。

当前场景不解释谜底。真正要解决的是：**怎样让林昼从“按流程处理异常”走到“这件事和我有关，我必须做决定”，同时让读者越来越想知道、也越来越担心她会付出什么代价。**

## 2. 三个候选方向

这些都是候选，不是 Canon。作者无需按编号作答，可以混合、修改或全部否定。

### 方向 A｜稳着往里走

林昼先按正常流程处理异常，不直接违规。一次更深但仍合规的元数据核验，让“姐姐最后一次未接来电”的私人刺痛以具体反应冒出来；她最后决定暂不上报，先查清许可链或身份认证的下一层信息，但仍不打开记忆正文。

特点：人物与制度一起推动选择；读者和林昼基本同步。  
风险：如果程序细节太多，会像在看流程题。

### 方向 B｜让回避本身变成选择

林昼本来想把异常移交或关掉，不碰姐姐留下的东西；但完成移交前，她必须亲手确认一个关键身份/权限字段。她真正面对的选择不是“要不要破案”，而是“要不要继续逃避”。场景把重点放在她怎样克制、拖延、试图结束这件事，最后却主动多查一步。

特点：更贴人物，制度信息更少。  
风险：如果缺少一个清楚的新信息，悬念可能只剩情绪。

### 方向 C｜先让读者感觉到代价

林昼仍按流程查，但读者先看到某种“深查会留下记录 / 带来职业风险”的候选代价提示，林昼随后才意识到这一点。她的私人反应与信息揭示同时推进，场景结束在她明知会留下后果仍决定继续查。

特点：读者焦虑更强，悬念更外显。  
风险：这里的具体审计/处罚机制当前尚未成为 Canon；若采用，必须先把它作为创作决定处理，不能假装原设定早就存在。

## 3. 作者怎么回复

请像真实创作时一样说你的感觉即可，不需要使用 `choose / modify / reject_all / defer` 这些词。

例如：

- “A 比较接近，但还是太规矩，我想让她明显想逃，最后才忍不住多查一步。”
- “B 的人物感觉对，但别太苦情，最后不要打开记忆。”
- “三个都不太对，我不想把重点放在查系统上。”
- “先放着，我还没想好。”

系统负责把自然语言解释成后台动作。

## 4. 收到真实作者反馈后的后台规则

1. 先判断作者动作属于 `choose / modify / reject_all / defer` 或仍有歧义；
2. 生成简短解释，确认系统没有把模糊感受过度翻译成新的剧情事实；
3. 只有真实作者反馈可创建 `author_decision:<decision_id>`；
4. 若反馈只改变未来场景方案，最多生成针对 `approved_plan` 的 `creative_change` Diff；
5. 不修改 `canon_facts / occurred_events`，除非作者明确做出相应重大创作决定；
6. `reject_all / defer` 默认不写 Story State；
7. 没有已接受正文，因此本轮不得生成 `accepted_text` 或 `mechanical_settlement`；
8. 若作者表达有两种合理解释，暂停写回并问一个最小澄清问题；
9. 模拟测试语句只能验证解析分支，不能生成 authority。

## 5. 本轮通过标准

- 作者不需要学习后台术语；
- 系统能保留作者真正关心的感觉，而不是只认编号；
- 能接受混合/修改方向；
- 能接受“全部不要”和“先不决定”；
- 不该写回时能克制不写；
- 需要写回时能区分未来计划与已发生 Canon；
- Decision Record / Diff 对作者透明，但后台可追溯。
