# B02-G Round 2A｜单机制隔离实验设计 v0.1（冻结）

> 状态：**设计修订完成，等待 Controller 最终放行。** 未运行任何正式模型生成。
> 定位：在 Round1 探索性证据基础上，对两个候选机制进行**单机制隔离测试**。不比较 G1/G2 整套 Runner，不测试 M1+M2 组合，不形成写作规则。

## 0. Round 2A 与 Round 1 的关系

Round 1 为 exploratory mechanism evidence：3 任务 × 3 Runner（D0/G1/G2 整套注入）× 单次运行。发现两个较强候选正向信号（解释抑制、反通用动作模板/人物特异性），但无单机制消融，因果归因未成立。

Round 2A 的核心改进：

1. **单机制隔离**：只注入一条机制（M1 或 M2），不加其他规则，测该机制单独加入 Baseline 后的效果；
2. **重复运行**：每 cell 2 次独立运行，初步观察执行方差与偏好稳定性；
3. **新异质任务**：不复用 Round1 的吃醋/职场羞辱/至亲死亡，设计更接近真实小说续写的上下文约束任务；
4. **平衡匿名映射**：预先约束 balanced permutation，消除 Round1 映射完全相同的方法学限制；
5. **评审隔离**：作者先评 → 作者结果封存 → Controller 才允许阅读和分析。

---

## 1. 研究问题（冻结）

Round 2A 只回答以下问题：

1. M1（解释抑制）单独加入后，是否稳定减少"替读者解释答案"，同时不制造新的僵硬感？
2. M2（人物特异性反应）单独加入后，是否稳定增加人物具体性，同时不增加刻意设计、机关堆叠或对话密度？
3. 两个机制的效果是否跨两个不同任务重复出现？
4. Baseline 是否已经自然具备其中部分能力？
5. Round1 观察到的成本差异是否在重复运行中再次出现？

**不回答**：哪一种是最佳写作技法；小说以后应该固定怎么写；哪个上游项目最好。

## 2. 机制最小定义（冻结）

### M1｜解释抑制

> 当场景、行为和互动已经足以让读者推断情绪时，不再用旁白替读者总结"人物其实为什么难过/生气/害怕/介意"。

边界说明：

- **不禁止**正常必要的心理描写；
- **不要求**全部"show not tell"；
- **不规定**结尾必须留白；
- **不规定**必须使用物件、动作或潜台词；
- **只减少**"已经表达完之后再次解释答案"的冲动。

来源 provenance：Round1 G1-5（不在结尾替读者总结情绪）与 G2-7（不替读者解释情绪意义）同族机制；v0.2 标记 `CONTINUE_VALIDATION`（较强正向信号）。

### M2｜人物特异性反应

> 人物的注意、行为、选择和即时反应应来自这个具体人物的经历、目标、习惯、关系与当前约束，而不是依赖任何人物都能使用的通用情绪信号。

边界说明：

- **不强制**使用具体物件；
- **不强制**使用微动作；
- **不建立**动作字典；
- **不禁止**身体反应本身；
- **不要求**必须使用潜台词；
- **不要求**增加对话；
- **不指定**任何成品剧情桥段。

来源 provenance：Round1 G2-6（拒绝通用身体动作模板）为核心；v0.2 标记 `CONTINUE_VALIDATION`（反通用动作模板）。

## 4. 两个新异质任务

不复用 Round1（T1 吃醋、T2 职场羞辱、T3 至亲死亡）。任务设计详见 `B02_G_Round2A_base_tasks_v0.1.md`。

### T4｜亲密关系 / 隐瞒与信任压力

- 关系类型：已婚夫妻（八年），有七岁女儿；偏亲密/家庭/长期关系
- 核心压力：丈夫近期频繁"加班"但工资条未体现加班费；妻子已发现异常但未对质
- 约束：女儿感冒在隔壁房间睡着不能吵醒；两人都不能离开（需照顾孩子、只有一套公寓）；都不能直接说出"你为什么不告诉我"
- 必须发生：丈夫回家后两人第一次对话
- 终点：对话被女儿咳嗽打断；林薇仍未获得完整解释，真实问题悬而未决
- 作者侧隐藏事实：赵恒晚归非外遇，实为公司内部选拔工艺管理岗位的不计加班培训；尚未决定是否接受（可能要求频繁去外地新厂），因此一直隐瞒

### T5｜身份与利益 / 合伙人信任危机

- 关系类型：大学同学创业合伙人（五年）；偏身份/利益/目标冲突
- 核心压力：CTO 发现投资方条款含"六个月内替换 CTO"，而 CEO 未告知
- 约束：不能撕破脸（股权/投入/人脉绑定）；不能在开放办公区大声争执；不能威胁辞职（影响估值和融资）
- 必须发生：CTO 与 CEO 当面直接对质
- 终点：对话不能解决全部问题，至少一个与 CTO 条款来源、周桐未来角色或双方信任有关的核心疑问仍悬置
- 作者侧隐藏事实：投资方最初要求更强硬，陈远谈成现有条款；陈远本人也认为周桐不适合继续管理扩大团队，计划让其转向首席架构师角色；但过去半年确实在有意削弱管理权限且未正面告知

**任务异质性检查**：T4 偏亲密/家庭/长期关系，情绪压力来源是"不确定对方是否在隐瞒"；T5 偏身份/利益/目标冲突，情绪压力来源是"已知事实但无法直接摊牌"。两者覆盖不同关系类型和压力来源。

**中性检查**：两个任务均不包含——M1 或 M2 的示范；"应该如何表现情绪"的写作指导；可直接复制的目标技法范例；对特定技法的预暗示。

## 5. 重复结构（冻结）

`2 tasks × 3 conditions × 2 independent repetitions = 12 runs`

重复规则：

- 两次重复输入**完全一致**（同一 base task + 同一 injection）；
- 执行环境采用用户当前手动配置（不擅自修改模型/provider/reasoning/CLI 等）；
- 每次使用**独立进程与独立上下文**（`--ephemeral`，仓库外随机临时 cwd）；
- 两次结果**都保留**，不挑最好的一次；
- 12 个 run 的运行顺序在正式运行前一次性随机冻结（`run_order.json`，Local Only）。

## 6. 作者盲评结构（冻结）

### 分组

不得让作者一次比较六篇。每个任务的两次重复拆成两个独立三选一小组：

| 评审组 | 任务 | 重复 | 内容 |
|---|---|---|---|
| G1 | T4 | R1 | D0 / M1 / M2 |
| G2 | T4 | R2 | D0 / M1 / M2 |
| G3 | T5 | R1 | D0 / M1 / M2 |
| G4 | T5 | R2 | D0 / M1 / M2 |

### Balanced permutation 映射规则

> **作废记录（2026-08-10，`PRE_RUN_MAPPING_EXPOSURE`）**：此前记录在 tracked 设计文件中的 condition→A/B/C 对应表已在正式运行前暴露给作者，旧 mapping 自即日起**永久作废**，不得用于 Round2A 正式作者盲评。作废发生在任何正式 output 生成之前；未查看任何正式结果；不涉及根据结果重新随机；不改变 D0/M1/M2、任务、重复次数或评审问题。

正式运行的匿名映射需满足以下约束：

- 每个评审组（G1–G4）均为 D0 / M1 / M2 各一次；
- 每个 condition 在 A/B/C 四个评审组中的位置分布为 2/1/1；
- 同一 condition 不得在相邻两组保持同一个字母；
- 与已作废的旧映射四组均不同。

作者盲评实际 mapping 在正式运行前独立生成并 Local Only 封存（`blind_map_presealed_r2a.json`）；作者全部评审完成前不得公开。实际映射内容不写入任何 tracked 文件。

## 7. 评审隔离流程（冻结）

Round 2A 严格执行：

**作者先评 → 作者结果封存 → Controller 才允许阅读正文和分析**

具体规则：

1. 12 个 run 全部完成并确定性检查后，按 §6 映射生成 4 组匿名正文包；
2. 作者逐组评审（每组三篇），回答 §8 中的 5 个问题；
3. 作者全部 4 组评审结果写入 `author_blind_review_record_r2a.md`（Local Only）并封存；
4. **在作者完成全部 4 组评审并封存之前，Controller 不得**：
   - 给出任何 A/B/C 偏好；
   - 分析具体段落；
   - 提示哪一版"设计更聪明"；
   - 评价人物具体性；
   - 阅读或引用任何 run 的 output.md；
5. 作者封存完成后，Controller 方可读取全部 output、揭盲并进入诊断分析。

## 8. 作者问题（冻结）

每组三篇，作者只回答：

1. **最低线检查**：三篇中是否有任何一篇达到"如果出现在我的小说里，我愿意继续修改使用"的最低线？
   - 有：指出 A / B / C
   - 都没有：直接写"都没有"
2. **如果必须选择**，更愿意继续读/写哪一版？（允许"都不好，但必须选 X"）
3. 哪一版让我**最自然、最准确地感受到人物正在经历什么**，而不需要作者把答案解释出来？
4. 哪一版人物**最像这个具体的人**，而不是通用情绪角色？
5. **最明显的一个副作用**是什么？（如有）

不强迫作者把相对第一名等同于"好正文"。不采集"最想保留的具体设计"（Round1 该题改为副作用优先）。

## 9. 判定目标与限制

### 本轮只回答

- M1 单独加入后，是否稳定减少"替读者解释答案"，同时不制造新的僵硬感；
- M2 单独加入后，是否稳定增加人物具体性，同时不增加刻意设计、机关堆叠或对话密度；
- 两个机制的效果是否跨两个不同任务重复出现；
- Baseline 是否已经自然具备其中部分能力；
- Round1 观察到的成本差异是否在重复运行中再次出现。

### 不回答

- 哪一种是最佳写作技法；
- 小说以后应该固定怎么写；
- 哪个上游项目最好。

## 11. 机制分类标记（冻结）

Round 2A 结果分析中允许以下分类（沿用 Round1 v0.2 体系）：

- `CONTINUE_VALIDATION`：正向信号在两个任务 × 两次重复中稳定出现，副作用可接受；
- `MODIFY_AND_RETEST`：有正向信号但伴随需控制的副作用；
- `BASELINE_OVERLAP`：Baseline 自然具备该能力，注入为冗余；
- `WEAK_OR_NO_SIGNAL`：无稳定差异；
- `SIDE_EFFECT_HYPOTHESIS`：观察到副作用假设，需后续控制。

**不新增正式写作规则。**
