# B02-G Base Prompt 机制泄露审计（v0.1）

> 日期：2026-08-09
> 对象：`06_工作区/01_待处理/B02_情绪传递Benchmark/00_控制/B02_G_base_tasks_v0.1.md` 中 T1 / T2 / T3 三个中性 base prompt
> 方法：逐条检查（a）是否暗示 G1 或 G2 核心机制；（b）是否要求只有 Treatment 才应该知道的方法；（c）是否通过禁止项反向提示模型应该怎么写；（d）是否给 D0 过多写作方法指导。

## 审查结论

**三个 base prompt 全部通过机制泄露审计。** 场景部分只包含故事事实、人物关系、场合、必须发生的事件与必须出现的叙事结果；输出要求只约束字数、正文格式与前提不可更改。未出现任何 G1 / G2 特有的方法指令。

## T1 爱情关系

| 检查项 | 结果 |
|---|---|
| 场景是否暗示机制 | 否。仅含：稳定感情基础；女方看到男方与更年轻、漂亮、互动自然的女性交谈；她在意但自尊强、不愿直接承认；男方最初未意识到。均为故事事实。 |
| 是否要求 Treatment 才知道的方法 | 否。无“回避/防御/误读/潜台词/身体反应”等任何方法要求。 |
| 禁止项是否反向提示 | 受控。唯一禁止项为“不得直接使用吃醋、嫉妒、酸、醋意”。该禁用只禁四个直接情绪词，未要求任何替代写法（未要求动作、心理链、潜台词或行为表现）；替代方法只存在于 G1/G2 注入块。三 Runner 同等适用，属于 Controller 指定的必要公平基线，不视为机制注入。 |
| D0 是否获得过多方法指导 | 否。D0 收到与 G1/G2 完全相同的基础题。 |

## T2 权力关系

| 检查项 | 结果 |
|---|---|

| 是否要求 Treatment 才知道的方法 | 否。未要求任何动作、潜台词、防御机制或心理链。 |
| 禁止项是否反向提示 | 无禁止项。 |
| D0 是否获得过多方法指导 | 否。 |

## T3 丧失

| 检查项 | 结果 |
|---|---|
| 场景是否暗示机制 | 受控。场景含“刚确认至亲意外死亡”“预期崩溃但异常冷静”“开始处理具体现实事务”“结束前需出现一个微小变化，让读者意识到冷静不等于没有受影响”。其中“微小变化”是 Controller 指定的必须叙事结果：只约束“必须发生什么”，未约束“如何发生”（未要求特定身体反应、象征物、回忆、爆发或心理解释）。具体做法只由 G1/G2 注入提供，不构成机制泄露。 |

| D0 是否获得过多方法指导 | 否。 |

## 输出要求（三任务共用）审查

“中文小说正文；目标 900–1200 中文字；只输出正文，不输出分析、提纲、说明或创作理由；不得改变故事前提”全部为中性约束，不包含任何写作方法。

## 附注

1. T1 的直接情绪标签禁用与 T3 的“微小变化”要求均来自 Controller 任务定义，属于“必要约束”，按 `B02_角色分轨与正式Runner前置决定_v0.1.md` 第三节的允许范围保留（只约束故事事实、必须事件、字数和明显禁用的情绪标签）。
2. 若 Controller 认为 T3 的“微小变化”要求仍可能被 G1/G2 借势，可进一步只保留“场景结束前需要出现一个读者可感知的变化”，但按当前措辞审查未发现机制泄露。
