# AI-write 项目推进记忆

> 保存跨会话必须记住的项目方向、重大决策和当前阶段。过程日志不放这里。

## 1. 最终目标

AI-write 是作者主导、AI 辅助的长篇小说工作台。

作者主要做：`看正文 → 说感觉/要求 → 接受/拒绝/继续修改 → 做重大创作取舍`。

系统主要做：`知识召回 → Context 编译 → Skill/Agent 路由 → 规划/写作/诊断/修改 → 连续性 → 状态回写`。

前期原著蒸馏和后期辅助创作是一条链：BKP 应在真实创作中由后台自动调用，而不是要求作者手动记忆技巧。

## 2. 长期原则

- Borrow-first；
- 案例只暴露问题，不决定架构；
- 普通能力用真实任务轻量验证；
- BKP 与原创 Canon 严格分离；
- **作者控制 ≠ 作者审批**；
- 正式创作阶段性冻结核心工作流；
- 长期文档只留稳定原则，不持续堆过程细节。

## 3. 已完成能力链

- G3：跨书、小量、可追溯 Retrieval 已验证；`NO_RAG_UPGRADE` 继续有效；
- G4-A：五类最小创作合同；
- G4-B：Author Intent + Story State + Creation Brief 可脱离聊天恢复；
- G4-C：真实 KnowledgeRetrieve + 少量 BKP 可以形成小 Context 和有边界的创作方向；跨书按问题自然发生，不强制多书。

G4-C 发现亲属哀伤/内疚 BKP gap，但不是 Retrieval 升级阻塞。

## 4. 当前 Gate

**G4｜创作上下文与作者决策最小闭环：ACTIVE / G4-D。**

G4-D 验证 Author Decision Loop：作者只用自然语言接受、修改、拒绝或暂缓，后台负责解释并决定是否形成 Decision Record / State Diff。

关键纪律：

- 真实作者反馈才可成为 `author_decision` authority；
- 模拟输入只可测试解析，不可写权威状态；
- `reject_all / defer` 默认不写 Story State；
- `approved_plan ≠ Canon`；
- 没有正文时不制造 `accepted_text`；
- 有歧义就询问，不猜；
- 作者不维护后台字段。

当前真实测试入口：`06_工作区/G4B_沙盒_雾港档案室/g4d/G4D_作者决策真实验证.md`。
