# AI-write 项目推进记忆

> 保存跨会话必须记住的项目方向、重大决策和当前阶段。过程日志不放这里。

## 1. 最终目标

AI-write 是作者主导、AI 辅助的中文长篇小说工作台。

长期仍要把参考作品知识、原创状态、写作、诊断和状态回写连起来；但当前阶段不继续展开未来写作系统。

## 2. 当前唯一主线

**单书蒸馏成品化。**

用户现在只关心：把一本书交给 Agent 时，需要怎样自动完成蒸馏、内部做几类分析、最后得到什么。

作者侧目标：

`指定一本书 → 一次启动 → BookProfile + 可检索 BKP + 简短完成报告`

## 3. 已有地基

- SourcePrepare v0.2.1：原始素材只读标准化；
- BookDistill v0.2：Base Scan、多视角 Discovery、BookProfile、Deep Dive、总编辑收敛、BKP Finalize；
- 《一九八四》《三体》已跑通过 vNext；
- BKP v0.1 已定义长期保存层；
- KnowledgeRetrieve 已能发现正式 BKP。

BookDistill 的主要问题已经不是理论缺失，而是作者侧操作仍不够简单。

## 4. 一本书内部蒸馏语义

SourcePrepare 不算文学蒸馏。

BookDistill 内部：

1. Base Scan；
2. 至少两个互补 Discovery Pass：长篇运行/读者动力、Reader/Page Craft；
3. BookProfile；
4. 0～N 个按需 Deep Dive；
5. 总编辑式 Finalize → BKP。

Deep Dive 次数不冻结。《一九八四》《三体》各 3 次专项只是验证样本，不是以后固定模板。

长篇可按章节/分块处理；“一个 Pass”是分析目标，不等于单次模型调用或一次性装入整本书。

## 5. 最终 BKP 的用途

BKP 是一部参考作品完成蒸馏后的长期知识资产。未来正常写作只检索 BKP，不重新蒸馏原著。

作者默认先看到 BookProfile 与最值得调用的创作问题；Observation、Inference、Work-specific Pattern、Evidence、Deep Dive 等由系统按需检索。

## 6. 当前开发缺口

需要一个单书编排入口，把已有零件串起来：

`书名/book_id → SourcePrepare 状态判断 → BookDistill 多 Pass → 自适应 Deep Dive → BKP Finalize → Retrieval 可发现`

优先复用已有实现，只补编排、状态判断、失败报告和必要恢复，不重写 SourcePrepare/BookDistill 核心。
