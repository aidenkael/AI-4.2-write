# AI-write 项目推进记忆

> 保存跨会话必须记住的项目方向、重大决策和当前阶段。过程日志不放这里。

## 1. 最终目标

AI-write 是作者主导、AI 辅助的长篇小说工作台。

作者主要做：

`看正文 → 说感觉/要求 → 接受/拒绝/继续修改 → 做重大创作取舍`

系统主要做：

`知识召回 → Context 编译 → Skill/Agent 路由 → 规划/写作/诊断/修改 → 连续性 → 状态回写`

前期原著蒸馏和后期辅助创作是同一条链：BKP 的价值最终要在真实创作中被后台自动调用，而不是让作者手动记住或检索技巧。

## 2. 长期原则

- Borrow-first；
- 案例只暴露问题，不决定架构；
- 普通能力用真实任务轻量验证；
- 六区成熟作者能力地图检查漏项，C01–C20 只做技术路由；
- 永久允许“重要但暂时无法命名”；
- BKP 与原创 Canon 严格分离；
- 正式创作阶段性冻结核心工作流；
- **作者控制 ≠ 作者审批。**

## 3. 作者控制的正式定义

作者负责：作品方向、审美、人物重大取舍、重要创作决定。

系统默认自动：知识检索、上下文装配、后台专业能力路由、连续性检查、从已接受正文提取明确事实、机械 Story State 结算。

需要作者显式确认：重大方向变化、真实冲突/歧义、正文尚未成立的新解释/新剧情。

Story State authority：

- `accepted_text`：明确文本事实；
- `author_decision`：重大创作决定；
- BKP / AI candidate / Context：不能直接成为 Canon authority。

## 4. 原著知识地基

BookDistill 当前正式方向：多视角直接读原著 + 总编辑收敛。

- 长篇运行/读者动力：oh-story + AI-Novel；
- Reader/Page Craft：creative-writing-skills；
- 必要 Developmental Deep Dive：Apodictic；
- BookDistill：回源核证、去重、组合效果、Scope/Boundary/Counterevidence/Confidence → BKP。

知识成熟度：

`Evidence → Observation/Inference → Work-specific Pattern → Cross-book Pattern → Creation-tested Heuristic → Production Rule`

G3 已证明跨书、小量、可追溯、有边界 Retrieval；结论 `NO_RAG_UPGRADE` 继续有效。

## 5. 核心上游

- AI-Novel：完整生产链、任务合同、状态回灌；
- oh-story：中文长篇拆解与读者动力；
- creative-writing-skills：Muse + 专业创作团队；
- Apodictic：Developmental Editing / Firewall；
- InkOS：Author Intent、Context Compiler、分支/状态治理；
- graphify-novel / NovelForge：Story Bible / source of truth；
- ani-book：渐进确认、人可读权威状态、已验收内容进入长期记忆。

真实问题出现时优先回到这些上游，不无限扩搜。

## 9. 一句话记忆

> **AI-write 的价值是让复杂后台尽量消失：从优秀作品中蒸馏创作智慧，创作时自动调用相关知识和技能，作者主要通过阅读、自然语言反馈和重大取舍来完成创作。**
