# AI-write 项目推进记忆

> 保存跨会话必须记住的项目方向、重大决策和当前阶段。过程日志不放这里。

## 1. 最终目标

AI-write 是作者主导、AI 辅助的长篇小说工作台。

作者主要做：

`看正文 → 说感觉/要求 → 接受/拒绝/继续修改 → 做重大创作取舍`

系统主要做：

`知识召回 → Context 编译 → Skill/Agent 路由 → 规划/写作/诊断/修改 → 连续性 → 状态回写`

前期原著蒸馏和后期辅助创作是一条链：BKP 的价值最终要在真实创作时被后台自动调用，而不是让作者手动记忆技巧。

## 2. 长期原则

- Borrow-first；
- 案例只暴露问题，不决定架构；
- 普通能力用真实任务轻量验证；
- 六区成熟作者能力地图检查漏项；
- BKP 与原创 Canon 严格分离；
- **作者控制 ≠ 作者审批**；
- 正式创作阶段性冻结核心工作流；
- 长期文档只留稳定原则，不因每次发现持续膨胀。

## 3. 作者控制

作者负责：作品方向、审美、人物重大取舍、重要创作决定。

系统默认自动：Retrieval、Context、后台专业能力路由、连续性、accepted text 明确事实提取和机械 Story State 结算。

Story State 合法 authority：
- `accepted_text`；
- `author_decision`；
- 必要 `manual_import`。

BKP / AI candidate / Context 不能直接成为 Canon authority。

## 4. 原著知识地基

BookDistill：多视角直接读原著 + 总编辑收敛。

知识成熟度：

`Evidence → Observation/Inference → Work-specific Pattern → Cross-book Pattern → Creation-tested Heuristic → Production Rule`

G3 已证明跨书、小量、可追溯、有边界 Retrieval；`NO_RAG_UPGRADE` 继续有效，除非后续真实任务出现阻塞。
