# 1. 项目最终目标

AI-write 的目标不是“自动替作者生成一本小说”，也不是“把 GitHub 小说项目都装进一个仓库”。

目标是建立一套能长期辅助不同题材、不同风格长篇小说的 AI 创作工作台：

```text
参考与研究
→ 作品构思
→ 故事规划
→ 场景 / 章节创作
→ 审阅与诊断
→ 修订
→ 状态回写
→ 下一轮创作
```

作者负责：作品方向、人物取舍、审美判断、重大创作决定。

系统负责：资料、记忆、检索、方案推演、上下文编译、诊断、连续性、状态同步与技术路由。

作者层尽量只面对：

`参考/研究 → 构思 → 规划 → 写 → 审阅 → 修改`

后台承担：

`Book Knowledge + Canon/Story State + Retrieval + Context Compiler + Planning + Writer + Reader/Critic/Editor + Continuity + State Writeback + Controller`

# 2. 长期开发原则

## 2.1 Borrow-first

默认：

`真实问题 → 查能力地图 / 成熟上游 → 最小真实测试 → 能借就借 → 只补剩余缺口`

AI-write 自研重点应收缩到：协议、路由、胶水、BKP、BookProfile 预算逻辑、中文长篇适配、作者控制和必要状态接口。

Writer、Critic、Reader、Planner、Canon、Memory、Continuity、RAG/KG、Story Bible 等若已有成熟实现，先借/改。

## 2.2 案例只负责暴露问题，不负责决定架构

正确路径：

`案例暴露问题 → 成熟作者完整能力地图 → 查成熟上游 → 少量跨作品验证 → 只补系统性缺口`

禁止围绕单个案例不断新增硬编码规则。

## 2.3 真实任务优先，Benchmark 不是主项目

普通能力默认轻量验证；只有长期核心规则、证据矛盾、固化错误代价高时才升级严格 Benchmark。

B02 / B09 的方法学经验保留，但不复制成每个能力都要跑的大型研究流程。

## 2.4 作者不是机器

系统不能要求作者手动挑十几个 Skill、维护几十份状态表、严格服从旧大纲。

作者偏离计划时：

`系统识别影响 → 说明后果 → 作者确认 → 更新计划 / Canon / Story State`

正式创作阶段默认阶段性冻结核心 Skill / 工作流，在卷末、阶段末或自然停顿点统一升级。

# 3. 参考书知识与原创作品状态必须严格分离

- **BKP / Book Knowledge**：参考作品中蒸馏出的知识资产；
- **Canon / Story State**：当前原创作品中的事实、人物、关系、时间、伏笔、承诺与状态。

BKP Pattern 不能污染原创 Canon；原创事实也不能写进参考书知识。

结构化权威状态是长期资产；向量、图谱、索引、Context Package 等默认是可重建派生层。

---

# 4. 原著蒸馏与 BKP 已确认原则

BookDistill 的目标不是制造漂亮总结，而是保存未来创作真正可能重新调用的作品智慧。

当前已确认的 Discovery：

```text
原著（最高事实源）
├─ 长篇运行 / 读者动力：优先借 oh-story + AI-Novel
├─ Reader / Page Craft：优先借 creative-writing-skills
├─ 必要 Developmental Deep Dive：优先借 Apodictic
└─ BookDistill 总编辑：回源核证 → 去重 → 组合效果 → 边界/反例/置信度 → BKP
```

长期纪律：

- 重要观察能力必须可以直接读原著；
- BookProfile 是导航/预算工具，不是过滤器；
- 允许跨句、跨场景、跨章节组合证据；
- 永久允许“重要但暂时无法命名”；
- Discovery 可以宽，最终 BKP 必须克制；
- 单书最高默认 Work-specific Pattern；
- 无法可靠抽象但有价值的内容可以长期保留为 Observation / Inference。

知识成熟度：

`Source Evidence → Observation / Inference → Work-specific Pattern → Cross-book Pattern → Creation-tested Heuristic → Production Rule`

# 5. 成熟作者完整能力地图：六区

1. **作品方向与判断**：读者、承诺、主题、类型、审美目标；
2. **故事运行能力**：结构、人物、关系、世界、信息、悬念、兑现、长篇动力、场景/章节；
3. **读者与文本效果**：情绪、注意力、期待、欲望、幽默、恐惧、审美、连续体验；
4. **页面写作能力**：语言、声音、POV、心理距离、对白、潜台词、感官、动作、细节、意象、留白、节奏；
5. **判断与修订能力**：Reader Sim、Critic、Editor、Developmental Editing、为什么有效/失效；
6. **长期知识与创作运行能力**：Book Knowledge、Canon、Retrieval、Context Compiler、作者意图、Continuity、状态回写、Controller。

永久入口：**重要，但目前无法命名。**

C01–C20 只作为技术路由，不是 20 个作者 Skill，也不是串行 Benchmark 排期。

# 8. 当前正式 Gate：G4｜创作上下文与作者决策最小闭环

**状态：ACTIVE。**  
**建立：2026-08-12。**  
**当前子阶段：G4-A｜成熟上游压缩成最小合同。**  
**启动记录：`00_项目控制/G4_启动记录_2026-08-12.md`。**

## 8.1 G4 为什么存在

G3 解决了 Retrieval，但留下两个 Phase E 正式问题：

1. **Cross-book Synthesis**：召回的参考智慧怎样结合当前原创作品情境，形成真正可用的方向；
2. **Author Decision Loop**：AI 怎样给方案/证据/风险/推演，而重大决定仍由作者掌握，并在确认后可靠写回状态。

这两件事共同依赖最小 Author Intent、Story State、Creation Brief、Context Compiler 与 State Diff，所以 G4 先做“神经中枢”，不先做 Writer。

## 8.2 G4 唯一目标

证明系统可以把：

`作者意图 + 当前 Canon/Story State + 当前创作焦点 + 读者目标 + 少量相关 BKP Hit`

编译成小而相关的 Context Package，再提出 1～3 个真正有差异的方向；作者可以选择、修改、全部拒绝；只有作者确认后才写回计划 / Canon / Story State。

G4 不负责证明正文质量。

## 8.3 G4 五种概念工件

- Author Intent；
- Story State / Canon；
- Creation Brief；
- Context Package；
- Decision Record / State Diff。

## 8.4 G4 Borrow-first 分工

- InkOS：主骨架；
- AI-Novel：任务合同；
- graphify-novel + NovelForge：Story Bible / Canon 数据纪律；
- ani-book：权威文件与确定性校验；
- creative-writing-skills：Muse 与多方案探索；
- Apodictic：诊断 Firewall；
- oh-story：中文长篇读者动力约束。

## 8.5 G4 子阶段

`G4-A 最小合同 → G4-B 可丢弃沙盒状态 → G4-C Context Compiler + Synthesis 原型 → G4-D Author Decision Loop → G4-E 收口`

当前只允许推进 **G4-A**。

## 8.6 G4 关键退出边界

G4 closeout 前必须证明：

- 权威状态可文件化，不依赖聊天；
- BKP 与 Canon 严格分离；
- Context Package 小而相关、来源清楚、可重建；
- 多类真实创作问题都能做情境化 Synthesis；
- 1～3 个方向真正有差异，并说明依据、边界、风险；
- 作者可以选择/修改/拒绝；
- 作者确认前不写 Canon，确认后有 State Diff / Decision Record；
- 新会话只读权威工件即可恢复当前状态和最近决定；
- 不因 G4 升级 Retrieval/RAG/KG；
- 作者明确验收后才能退出。

完整 14 项退出条件见 `G4_启动记录_2026-08-12.md` 和 `项目阶段门禁.md`。

## 8.7 G4 明确不做

- 完整 Writer；
- 完整 Reader Sim / Critic / Editor；
- 正式长篇；
- UI / Obsidian 插件 / 独立客户端；
- 大型数据库、KG、向量库、多 Agent 平台；
- KnowledgeRetrieve 升级；
- 超级 Canon schema；
- BKP 自动写入 Canon；
- AI 自动替作者决定重大方向；
- 后续 Gate 功能。
