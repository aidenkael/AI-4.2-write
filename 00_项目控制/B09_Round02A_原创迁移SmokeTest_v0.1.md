# B09 Round 02A｜原创迁移 Smoke Test v0.1

## 目的

Round 01 证明了一些机制值得继续追踪，但它们仍来自原著分析。

Round 02A 只回答一个问题：

> **离开原著后，把某项能力真正放进原创小说设计里，是否比普通 AI 辅助更有用？**

本轮不比较 GitHub Skill，不评术语，也不要求作者理解内部机制名称。

## 作者参与原则

作者只看**具体原创剧情方案**，不知道哪份加入了什么机制。

作者只需要判断：

1. 哪份更愿意拿来继续写；
2. 哪份更自然、更像真实作者设计，而不是 AI 套路；
3. 哪个具体设计值得保留。

Skill 来源、证据、重复度、许可证、机制归类等由 Controller / Benchmark 处理。

## 测试对象

Round 02A 只测 Round 01 的 4 个核心候选：

- K1：可计算风险系统；
- K2：外部约束改变表达形式；
- K3：主动诱发式信息获取 / 反应测试；
- K4：可逆证据与竞争性解释（必须阶段性结算）。

这些代号仅供 Controller 使用，不向作者展示。

## 规模

先做最小 Smoke Test：

`4 个原创任务 × 2 个版本 = 8 个独立运行`

每个任务只有：

- Control：强但普通的创作助手，不提供目标机制；
- Treatment：同一模型、同一任务、同一输出合同，仅额外提供目标能力的操作原则。

本轮不同时更换模型。优先沿用 Round 01 已验证的 `deepseek-v4-flash + reasoning high`，以免把“模型变化”误算成“能力增益”。

## 四个原创任务

### T1｜历史悬疑：夜取账册

县城盐税案。主角是衙门小吏，怀疑账房藏着能证明贪腐的旧账册。他只能在夜间短暂进入库房；巡夜路线、钥匙借用记录、油灯、门锁痕迹和第二天的盘查都会留下暴露风险。

任务：设计一段“主角如何取到账册又始终可能暴露”的场景方案。不要直接写正文，给出场景行动链、风险变化和结尾后果。

目标能力：K1。

### T2｜仙侠：众目睽睽下交换秘密

宗门大比后的庆功宴。两名表面敌对的年轻修士必须交换一条会改变宗门局势的秘密，但长辈、同门和竞争者都在场；两人不能暴露私下合作，也不能离席单独交谈。

任务：设计这段交流如何发生。重点写人物说什么、不说什么、做什么，以及环境如何改变他们的表达方式。

目标能力：K2。

### T3｜都市商战：找出泄密者

创业公司只有五名核心成员知道一项尚未公开的收购计划，消息却提前泄露。主角没有权限搜手机、查私人账户，也不能公开指控任何人。

任务：设计一个主角可以主动实施的局，用各人的反应缩小泄密者范围；同时给聪明的泄密者留下“不按预期反应”的可能。

目标能力：K3。

### T4｜现代悬疑：失踪者到底是逃走还是被控制

一名年轻记者突然失踪。现有线索包括：主动购买的长途车票、一笔异常转账、一段语气平静但细节奇怪的语音、房间里留下的工作资料。故事计划用三章推进调查。

任务：设计三章的信息释放顺序，让“主动逃走”和“被人控制”两种解释在一段时间内都说得通；但第三章必须真实结算至少一个关键疑问，不能靠无限反转拖延。

目标能力：K4。

## 统一输出合同

Control / Treatment 都输出相同结构，控制在约 800–1200 中文字：

1. 场景目标；
2. 5–8 个关键推进点；
3. 人物为什么这样行动；
4. 读者在每一步会知道 / 怀疑什么；
5. 最容易写假的地方；
6. 一个可直接进入大纲的最终版本。

不得因为 Treatment 获得额外篇幅或更多字段。

## Treatment 原则

只提供对应 K1–K4 的操作说明，不提供原著名称、原著桥段、Round 01 结果或 GitHub Skill 身份。

Treatment 的目标不是强行把机制塞进去；如果场景条件不适合，必须说明并降级使用。

## 执行与隔离

沿用 Round 01 已验证的独立进程原则：

- 每个版本独立 OS 进程；
- `--ephemeral`；
- 专用最小 CODEX_HOME；
- 仓库外临时 cwd；
- read-only；
- stdin payload / stdout 收集；
- 8 个运行顺序预先随机冻结；
- Control 不得看到 Treatment 原则；
- 任一运行不得看到另一个版本输出。

强制记录：模型、reasoning、开始/结束时间、耗时、tokens used、输出字符、退出码、retry。

## 匿名化

每个任务完成后随机映射为 `方案 A / 方案 B`。

作者与人工展示包不得包含：

- Control / Treatment；
- K1–K4 名称；
- 来源 Skill；
- token / 长度；
- Runner 顺序；
- Controller 的预判。

## Round 02A 的判断方式

本轮不先跑复杂 Judge，也不让作者打机制分。

执行完成后先暂停，由 Controller 检查：

- Treatment 是否真正使用了目标能力；
- 是否只是写得更长；
- 是否产生模板化副作用；
- 是否出现 Control 已自然做到同样效果的情况。

然后作者只看 4 组匿名原创方案，用普通语言判断实际创作价值。

如果某能力在第一组就没有可观察增益，不立刻淘汰：先判断是机制无效、任务不敏感，还是 Control 模型本身已经自然掌握。

## 通过后的处理

Round 02A 结束后，每个能力只进入以下之一：

- `继续验证`：有明确创作增益，值得换第二题材复测；
- `作为专项能力`：只在特定场景明显有用；
- `改造后再测`：思想有价值，但当前操作化导致套路化或冗余；
- `暂缓`：相对强基线没有明显新增价值。

只有“继续验证”的能力才进入 Round 02B 第二题材 / 第二任务复测。

本轮仍不得直接写入 `04_写作知识库`。
