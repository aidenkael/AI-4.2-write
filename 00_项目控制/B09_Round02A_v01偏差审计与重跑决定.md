# B09 Round 02A v0.1 偏差审计与重跑决定

## 结论

Round 02A v0.1 的 8/8 独立运行、隔离、成本记录与结构检查均成功，可作为工程 pilot 保留；但**不能作为能力增益的正式 A/B 证据**。

原因有两项。

### 1. 基础任务泄露了目标机制

Control 本应只收到“作者想解决什么问题”，但 v0.1 的四个基础任务已经直接提示了目标操作：

- T1 预列钥匙、油灯、门锁、盘查等暴露风险；
- T2 直接要求“环境如何改变表达方式”；
- T3 直接要求“主动实施一个局，用反应缩小泄密者范围”；
- T4 直接要求“两种解释并存且第三章阶段性结算”。

因此 Control 已经获得了目标能力的大部分操作信息，Treatment 的新增量被严重压缩。两版自然收敛不能证明机制无效，也不能证明机制有效。

### 2. 人工盲评映射在汇报中被公开

执行完成汇报直接列出了各任务 `方案 A / 方案 B` 对应 Control / Treatment 的映射。作者已看到映射，因此 v0.1 的展示包不能再用于有效盲评。

## 处置

- v0.1 全部 Local Only 产物保留，不删除、不重写；
- v0.1 只记为“原创迁移工程 pilot”，不进入能力有效性结论；
- 不根据 v0.1 判断 K1–K4 继续/淘汰；
- 使用修正后的 v0.2 重新运行 4×2=8 组。

## v0.2 修正原则

1. Control 题目只描述创作目标、人物处境和必要事实，不暗示解决方法。
2. Treatment 在完全相同基础题后，才附加目标能力操作原则。
3. A/B 映射在作者完成 4 组简单选择之前绝不出现在聊天、展示包或普通执行汇报中。
4. 作者只看具体方案，回答“更想继续写 / 更自然 / 最想保留哪个设计”，不评术语。
5. Controller 负责后续解释能力来自哪里、什么时候应该调用。
