## 2. 唯一核心目标

证明 AI-write 可以在**不依赖聊天记忆、不把整个项目/全部 BKP 塞给模型、不自动替作者做重大创作决定**的前提下，把：

```text
作者意图
+ 当前作品状态 / Canon
+ 当前创作焦点
+ 希望读者经历什么
+ 少量相关 BKP 知识
```

编译成一个小而相关、来源清楚的创作上下文，并进一步：

```text
提出 1～3 个真正有差异的可行方向
→ 说明各自依据 / 风险 / 冲突 / 边界
→ 作者选择 / 修改 / 全部拒绝
→ 只在作者确认后更新计划 / Story State
```

G4 **不负责证明正文已经写得好**。Writer、Reader/Critic/Editor 的完整生产闭环不属于本 Gate。

---

## 3. G4 要解决的两个正式问题

### A. Cross-book Synthesis｜跨书智慧的情境化综合

G3 已证明 Retrieval 能把 BKP 中已有知识小量、跨书、可追溯地召回，但没有证明这些知识能结合当前原创作品情境形成真正可用的创作方向。

G4 要验证：

`作者意图 + Story State + 读者目标 + Creation Brief + 少量 BKP Hit`

能否被综合为少量不同方向，同时保留适用条件、冲突、边界和参考来源。

禁止“多数书都这么写，所以这是规则”。

### B. Author Decision Loop｜作者决策反馈环

正式目标：

`AI 给方案 / Evidence / 风险 / 推演 → 作者选择 / 修改 / 拒绝 → 作者确认后才写回计划 / Canon / Story State。`

系统必须提高作者判断力，而不是把作者从重大创作决策中删除。

## 4. Borrow-first 上游分工

G4 不选“总冠军”，也不把七套系统并存。只借各自最成熟的一段，再收敛成 AI-write 的薄协议。

### InkOS｜主骨架参照

优先借：`author_intent`、`current_focus`、chapter intent、Context Compiler、protected/compressible context、未来分支推演、作者确认前不污染 Canon、确认后状态写回、运行时状态治理。

### AI-Novel-Writing-Assistant｜创作任务合同

优先借：书/卷/章/场景分层任务；Reader Experience Contract 中的核心问题、承诺回报、即时欲望、阻力、情绪/信息变化、章末净变化和钩子责任；规划/生成/验收共享同一任务合同的思想。

G4 不启动自动导演和整本书自动生产。

### graphify-novel + NovelForge｜Story Bible / Canon 数据纪律

优先借：source of truth 与派生层分离、chapter→state 更新、character/world/thread 跨章状态、结构化卡片 / schema / 上下文注入思想。

G4 不建立大型 Knowledge Graph 或数据库。

### ani-book-skill｜权威文件与确定性校验

优先借：Markdown/YAML 等人可读权威工件、脚本只做确定性校验、派生索引可重建、作者确认后才进入长期事实。

### creative-writing-skills｜作者入口与探索

G4 只借 Muse 式作者入口、Brainstormer / Character Sim 的多方案探索和后台专业角色隐藏路由。完整 Writer / Reader / Critic / Editor 暂不实现。

### Apodictic｜决策诊断 Firewall

借：指出问题、风险和解决方案类别；contract / reader promise / decision pressure 等用于比较方向；不替作者写死内容。

### oh-story｜中文长篇读者动力约束

只把期待/回报、压力/换气、章节推进责任、关系/信息/情绪净变化、追读动力等少量概念进入 Creation Brief 和方案比较。

## 5. G4 只验证五种概念工件

### 5.1 Author Intent

至少回答：作品想成为什么；作者当前最在意什么；明确不想要什么；当前故事段 / 当前 1～3 章 focus 是什么。

### 5.2 Story State / Canon

保存原创作品的权威事实与当前状态：世界事实、人物状态、关系状态、已发生事件、当前悬念/伏笔/承诺、已确认计划。

**BKP 参考知识不得混入 Canon。**

### 5.3 Creation Brief

当前创作任务合同，至少表达：当前问题、主体人物欲望/阻力、希望读者经历什么、必须继承的事实/承诺、硬约束、允许自由探索的空间。

### 5.4 Context Package

派生上下文，不是权威事实：

```text
Author Intent
+ Current Focus
+ relevant Canon / State
+ relevant Outline / Thread
+ Creation Brief
+ KnowledgeRetrieve 返回的少量 BKP Hit
→ Context Package
```

必须有来源、选择理由、规模控制意识、可重建性；不得全量塞项目或 BKP。

### 5.5 Decision Record / State Diff

每个方向说明优势、风险、关键代价、参考知识与边界；作者可选择、修改、全部拒绝；确认前不更新 Canon；确认后生成明确 State Diff 与 Decision Record，能追溯“为什么变成现在这样”。

## 6. G4 子阶段

### G4-A｜成熟上游压缩成最小合同

当前第一子阶段。

只定义 Author Intent、Story State、Creation Brief、Context Package、Decision / State Diff 的**最小字段与权威/派生边界**。不把各上游 schema 整包搬进来，不先写大系统。

### G4-B｜建立一次性原创沙盒状态

在 `06_工作区` 建可丢弃的小型原创故事种子，只用于验证后台。不得把正式 `03_作品工程` 当试验场。

### G4-C｜Context Compiler + Cross-book Synthesis 最小原型

允许 Markdown / YAML / JSON + Agent 语义选择 + 少量确定性脚本；直接复用 KnowledgeRetrieve；不需要数据库、向量库或 KG。

### G4-D｜Author Decision Loop 验证

至少验证：选择一个方向；修改方向后确认；全部拒绝重新探索；作者临时偏离旧计划，系统先说明影响再按确认更新状态。

### G4-E｜收口判断

只判断这个最小“神经中枢”是否成立。不因为 G4 成立就声称 Writer / Reader / Critic 已完成。

## 7. G4 最小退出条件

只有同时满足以下 14 项，且作者明确验收，才允许退出 G4：

1. 有一个可丢弃原创沙盒；Author Intent、Current Focus、最小 Story State 可以文件化保存，不依赖聊天记忆；
2. Canon / Story State 与 BKP 参考知识严格分离；
3. Creation Brief 能触发 Context Compiler，从项目状态和 KnowledgeRetrieve 中只选少量相关信息；
4. Context Package 能说明信息来源和选择理由，不需要全量塞入项目/BKP；
5. 至少对“偏人物 / 偏情节信息 / 偏读者体验”不同创作问题验证情境化 Cross-book Synthesis；
6. 每次输出 1～3 个真正有差异的方向，不是同义改写；
7. 每个方向说明为什么适合当前作品、用了哪些参考知识、适用边界、主要风险/代价；
8. 作者可以选择 / 修改 / 全部拒绝，AI 不把多数意见或参考作品经验当规则强推；
9. 作者确认前 Canon / Story State 不发生正式写入；确认后有明确 State Diff / Decision Record；
10. 作者偏离旧计划时，系统能先说明影响，再按作者确认更新计划/状态；
11. 重开新会话 / 新 Agent，只读权威工件即可恢复当前作品状态和最近一次重大决定；
12. 不修改 KnowledgeRetrieve、不升级 RAG/KG，除非真实验证出现阻塞性检索问题；
13. closeout 时同步项目控制文档、长期手册和 provenance；
14. 作者明确验收后才能退出 G4。

## 8. G4 明确禁止事项

- 不直接实现完整 Writer；
- 不直接实现完整 Reader Sim / Critic / Editor；
- 不跑正式长篇；
- 不把 `03_作品工程` 正式作品当工具试验品；
- 不开发 UI / Obsidian 插件 / 独立客户端；
- 不建立大型数据库、Knowledge Graph、向量库；
- 不升级 KnowledgeRetrieve，只为“看起来更先进”；
- 不建立大型多 Agent 平台；
- 不把所有上游 schema 合并成超级 schema；
- 不因为一个沙盒就冻结最终 Canon schema；
- 不让参考书知识自动写入 Canon；
- 不让 AI 在作者确认前修改重大 Story State；
- 不让 Controller 自动替作者选择重大创作方向；
- 不整体照搬 AI-Novel 的自动导演产品哲学；
- 不因为 Phase E 很大就顺手做下一 Gate 的功能。
