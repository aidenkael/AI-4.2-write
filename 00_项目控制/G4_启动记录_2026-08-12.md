## 2. G4 为什么存在

G3 证明了 Retrieval，但没有证明参考知识能结合当前原创状态形成可用方向，也没有证明作者只说自然语言感觉时，后台可以正确维护计划与状态而不夺权。

G4 因此只验证创作“神经中枢”，不实现完整 Writer。

## 3. 产品约束

> **作者主要看正文、说感觉、做重大取舍；后台自动选择技能、调用知识、处理上下文、连续性和状态维护。**

**作者控制 ≠ 作者审批。**

## 5. 关闭依据

G4 已证明：

1. Author Intent / Story State / Creation Brief 可脱离聊天恢复；
2. BKP / Context / AI candidate 与原创 Canon authority 可以严格隔离；
3. 真实 KnowledgeRetrieve 与少量 State/BKP 能形成小而相关的 Context；
4. 人物、情节/信息、读者体验三类问题可形成有边界、有差异的候选方向；
5. 跨书综合按问题自然发生，不强制跨书；
6. 真实作者自然语言反馈可形成可追溯 `author_decision`；
7. 作者对未来场景的修改只更新 `approved_plan`，不会伪装成已发生 Canon；
8. choose / reject_all / defer / ambiguity 可被识别，模拟输入不获得 authority；
9. `state_rev` 变化后旧 Context/Brief 会被判为 STALE，旧 Diff 不能覆盖新状态；
10. `accepted_text → mechanical_settlement` 的分类/authority/歧义边界已做非权威 dry-run，协议成立；
11. 当前没有 Retrieval / RAG / KG 升级阻塞。

G4-E 验收：`06_工作区/G4B_沙盒_雾港档案室/g4e/G4E_CLOSEOUT.md`。

## 6. 关闭时特别处理的两个尾巴

### 6.1 旧 Context 失效

G4-C 三份 Context 与 `brief-001` 建于 `state_rev=1`。G4-D 应用真实作者决定后状态变为 `state_rev=2`，因此这些旧派生物已明确标记 STALE / historical，禁止未来直接复用。

### 6.2 accepted_text 条件的范围

G4 明确不实现完整 Writer，因此不能假装生产级 accepted-text 自动提取已经跑通。G4-E 只用非权威 fixture 验证：若正文已被接受，文本直接成立的事实可归类为 `mechanical_settlement`；需推断的内容不能自动写回。

这满足 G4 的**协议边界验证**，但不代表未来 Writer/runtime 集成已经完成。
