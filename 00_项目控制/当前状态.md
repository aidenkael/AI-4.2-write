### 长篇正文与上下文

正式正文物理存储按章：`03_正文/第001章.md`、`第002章.md`……；只有作者接受的版本进入正式正文。

运行与 acceptance 使用稳定的 scene/write-turn ref；同一章可包含多个 accepted ref，不强迫小说采用固定场景结构。REAL_PROJECT_WIRING 需维护最小的 accepted ref → 正文章节映射，使 `accepted_text:<scene_ref>` 能追溯到正式正文。

每次写作不重读全文。上下文继续使用已冻结的分层策略：

- 长期连续性：Story State
- 未来方向：当前 active approved_plan
- 当前任务：ContextCompiler 只选择少量相关 State，空 selection 不 fallback 全 State
- 短期文字连续性：最近 accepted 正文末尾约 1000–2000 字 recent prose
- 久远具体原文：有真实需要时定向读取对应章节
- 参考写作知识：明确 knowledge need 时少量 BKP；0 BKP 合法

当前不建设原创正文全文 RAG、embedding、vector DB。

### acceptance 生产链

目标机械链：

`候选正文 → 作者明确接受 → 写入/更新对应章节 Markdown → 登记 accepted scene ref → mechanical settlement → 更新该作品 production Story State → 下一轮基于新 State + recent prose 继续`

未接受草稿不得写入正式正文，不得触发 production Story State 结算。

## blind #2 复现结论（2026-08-24）

**BLIND_2_CLASSIFICATION = DETERMINISTIC_DEFECT**

原始 blind #2 本身不是正式 runtime/authority 污染：T2 未消费 T1 实际 BKP，而是使用裸 K 编号自行编写知识卡身份，并额外引用不存在的 K016；随后 Context 按真实 BKP anchor 注入了真实卡内容。因此原始案例的主要根因属于模型/检索生成层 identity mismatch，而不是“伪造卡内容被 runtime 当真”。

但 synthetic collision 证明了独立的确定性完整性缺陷：当不同 `book_id` 同时存在相同裸 `source_anchor`（例如 `book_a/K001` 与 `book_b/K001`），`selected_knowledge_ids=["K001"]` 会把两个 hit 静默同时注入 Context，没有歧义拒绝或 gap。

其余守卫均正常：
- missing ref 不注入，并产生 BKP gap；
- project A planning token 不能确认到 project B；两边正式状态保持不变；
- canceled request、replay、stale state 均被拒绝/失效；
- 调查未修改 production/tracked 文件。

当前只修 synthetic collision 已机械证明的最小缺陷；不因原始 blind #2 的模型身份伪造顺手重做 KnowledgeRetrieve、BKP schema 或模型治理。
