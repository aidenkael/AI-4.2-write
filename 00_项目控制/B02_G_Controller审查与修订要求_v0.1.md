# B02-G｜Controller 审查与修订要求 v0.1

> 日期：2026-08-09
> 状态：正式运行前修订要求

## 一、审查结论

B02-G 的总体协议、三组中性 base task、隔离、重试、成本记录与匿名评审设计可以保留；但当前 G1/G2 注入文本存在“具体示例直接贴近测试题”的污染风险，正式运行暂不放行。

## 二、必须修正的问题

### 1. G2 对 T3 存在直接内容提示

当前 G2 注入第 4 条含有具体示例：人物反复伸手摸手机想给已经去世的人发消息，然后想起对方不在了。

这不是纯机制说明，而是一个几乎可以直接用于 T3“至亲死亡、异常冷静、微小变化”的成品剧情动作。若保留，G2 在 T3 获得了额外场景创意，不再只是获得写作机制，比较会被污染。

处理：删除该具体示例，只保留抽象机制，例如“内心性可通过行为、记忆或联想显现，不必直接贴情绪标签”。

### 2. G1 的具体示例与结尾处方也会给 T3 提供内容脚手架

G1 第 4 条列出“多年相处时间、反复出现的物品、固定日常动作”等具体承载方式；第 5 条进一步规定“结尾余韵用安静细节完成”，并给出“继续做一件日常动作、不解释、不回头、不流泪”等具体形式。

其中第 5 条与 T3 的“异常冷静 + 结尾出现微小变化”高度贴合，容易让 G1 得到测试题专用答案形状。

处理：保留“关系与情绪应由具体、人物化的细节承担”和“避免结尾替读者总结情绪”的原则；删除题目相关的具体示例、固定结尾模式和动作清单。

### 3. 正式 Treatment 注入不应携带可直接挪用的剧情例子

B02-G 首轮目标是比较机制增量，不是比较哪家上游刚好提供了与题目相似的示例。因此 G1/G2 最终注入统一执行：

- 不放入与 T1/T2/T3 可直接对应的成品行为、物件、台词或结尾例子；
- 若上游规则只能通过示例理解，由适配器改写为抽象机制，并在 manifest 保留来源路径；
- 不因为删除示例而新增 AI-write 自创技巧，只做“去案例化”。

## 三、Base task 决定

T1、T2 保持不变。

T3 当前“场景结束前，需要出现一个微小变化，让读者意识到这种冷静并不等于没有受到影响”可以保留。它定义的是必须达到的叙事结果，而不是实现方法。真正需要清理的是 Treatment 注入中的题目相关答案脚手架，而不是继续把 base prompt 改得更模糊。

## 四、其余协议决定

以下设计通过 Controller 审查，可保持：

- D0 / G1 / G2 三 Runner；
- 3 任务 × 3 Runner = 9 次独立运行；
- deepseek-v4-flash，reasoning high；
- 独立 OS 进程、仓库外 cwd、read-only、ephemeral；
- 同任务共享完全相同 base prompt；
- 900–1200 中文字，只输出正文；
- 统一 timeout / retry；
- 运行前一次性随机冻结顺序；
- 全量记录 token、耗时、字符数和 retry；
- 输出完成后再匿名化；
- 作者只看匿名正文，不看 Runner、来源、token 与成本。

## 五、修订后放行条件

Agent 只需：

1. 对 G1/G2 做去案例化修订；
2. 重生成 6 个 Treatment runner 输入（T1/T2/T3 × G1/G2），D0 不变；
3. 更新 runner_manifest 的字符/token 成本与逐条来源；
4. 做一次“Treatment 内容提示污染审计”，确认注入中不存在可直接挪用到三个测试题的具体剧情答案；
5. 更新协议版本/状态，提交后暂停。

修订完成后由 Controller 只复核最终 G1/G2 注入；若通过，即可放行正式 9-run，不再重新设计 base task 或候选池。

## 六、边界

- 不设计 AI-write Candidate；
- 不启动 B02-R；
- 不改 B09；
- 不运行正式生成，直至 Controller 再次放行。
