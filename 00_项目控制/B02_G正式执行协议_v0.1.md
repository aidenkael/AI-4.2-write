## 1. 参赛 Runner 与规模

- `D0`：strong baseline，同模型，无额外小说 Skill。
- `G1`：oh-story 最小情绪 / 中文正文生成机制子集（`B02_G_runner_inputs/G1_injection.txt`）。
- `G2`：creative-writing-skills 最小 Writer / Character Sim 生成机制子集（`B02_G_runner_inputs/G2_injection.txt`）。
- Apodictic 不参加 B02-G；不设计 AI-write Candidate。
- 规模：`3 任务 × 3 Runner = 9 个独立运行`。

## 2. 固定执行条件

| 项 | 固定值 |
|---|---|
| 模型 | `deepseek-v4-flash` |
| Reasoning | `high` |
| Provider | deepseek（api.deepseek.com，responses API） |
| CLI | `codex-cli 0.147.0-alpha.6.5` |
| 启动方式 | `codex exec -C <仓库外临时cwd> --skip-git-repo-check -s read-only --ephemeral -m deepseek-v4-flash -c model_reasoning_effort=high -c tools.shell=false -c tools.web=false -o <out> -` |
| 输入 | stdin payload（对应任务的 D0/G1/G2 runner 输入文件全文） |
| cwd | 每次运行新建仓库外随机临时目录 |
| 进程 | 每次独立 OS 进程，`--ephemeral`，不持久化会话 |
| Base task | 同一任务三 Runner 使用完全相同 base prompt |
| 输出长度 | 目标 900–1200 中文字；只输出正文 |
| Timeout | 每运行 900 秒 |

## 3. 隔离规则

- Runner 之间不得读取其他 Runner 输出：仓库外 cwd、禁用 shell/web 工具、输入只含本 Runner 自己的文件内容。
- 不注入任何仓库路径、其他 Runner 路径或上游冻结副本路径。
- 上一个任务不得污染下一个任务：每次运行全新进程、全新临时 cwd、`--ephemeral`。
- 作者评审前不暴露 D0/G1/G2 身份、上游来源、token、耗时、文件数量或 Runner 长度。

## 4. 成本与元数据记录

每运行强制记录：

- 模型、reasoning、CLI 版本；
- started_at / finished_at / 耗时（秒）；
- input tokens 与 output tokens（CLI 报告可得值；不可得则记录 unavailable）；
- 输出总字符数与中文字符数；
- process exit code；
- retry_count；
- 运行顺序（运行前随机冻结，生成后不得调整）。

## 5. Retry 规则

- 触发条件：process exit != 0，或 `-o` 输出文件缺失/为空。
- 处理：使用全新独立进程重试一次，输入、模型、参数完全一致；`retry_count = 1`。
- 首次失败产物保留留档；基础设施失败不计为内容失败。
- 重试仍失败：停止该运行并上报 Controller，不擅自扩大权限或改提示。

## 6. 运行顺序

- 9 个 run id 在正式运行前一次性随机冻结并保存（`run_order.json`，Local Only）；
- 生成后不得根据输出调整顺序；
- 同一模型、同一参数贯穿全部运行。

## 7. 匿名化与作者评审

- 正式输出全部完成并确定性检查后，每个任务随机映射 D0/G1/G2 → `方案 A / B / C`；
- 映射仅保存在 Controller-only 文件，作者评审前不得公开；
- 作者评审界面只显示三个匿名正文，不显示 token、耗时、文件数量或 Runner 长度；
- 作者每组只回答：
  1. 哪个版本更愿意继续读 / 写；
  2. 哪个更自然；
  3. 哪个人物更像一个具体的人，而不是“通用情绪演员”；
  4. 最想保留的一个具体设计；
  5. 最明显的副作用（如有）。
