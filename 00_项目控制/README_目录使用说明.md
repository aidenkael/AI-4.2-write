# AI-Wirte 项目说明（目录结构与工作流）

> 本文件是当前目录结构的**权威说明**。任何目录调整都必须先更新本文件，并经明确授权。

## 一、最终目标

本项目不是一个资料管理系统，也不以囤积小说全文作为“训练数据”。

目标是：**用 AI 辅助真实作者完成创作流程，逐步形成一个能产出高质量长篇网络小说的创作系统。**

当前重点是 AI 辅助创作，不是模型训练工程。

## 二、八个顶层目录

- `00_项目控制`：项目说明、规则、索引、迁移与整理报告、资产清单等控制类文档。
- `01_原始素材`：未加工的原始资料（第三方网络小说、世界文学、历史/古代资料、现代专业资料等）。**Local Only，不进入 GitHub。**
- `02_原著蒸馏`：从具体作品中提炼的结构、人物、节奏、叙事、技法、案例等分析结果。当前暂不建立具体蒸馏体系。
- `03_作品工程`：我们自己正在创作的作品（设定、大纲、人物、章节、正文）。**最终创作发生的位置。**
- `04_写作知识库`：跨作品可复用的写作知识、方法、案例、规律。
- `05_Skills与自动化`：Agent / Skill / 脚本 / 自动化能力。
- `06_工作区`：只处理中间状态，不作为长期知识库。
- `99_归档`：失效但需要保留的项目资料。

未经明确授权，不得新增顶层目录，不得恢复旧目录体系。

## 三、资料生命周期（从进入到被创作使用）

```
01_原始素材  →  06_工作区  →  02_原著蒸馏  →  04_写作知识库  →  03_作品工程
```

1. 原始资料进入 `01_原始素材`（本地保留）。
2. 在 `06_工作区` 做中间处理。
3. 从作品提炼的分析进入 `02_原著蒸馏`。
4. 可复用的方法 / 规律进入 `04_写作知识库`。
5. 最终创作在 `03_作品工程` 落地。

## 四、Local Only 原则

第三方网络小说、世界文学等原始全文**默认只允许保存在本地**。`01_原始素材` 下的原始格式（epub / txt / zip / pdf / azw3 / mobi）已被 `.gitignore` 禁止上传。

这些资料用于研究，不是可公开再分发的素材。

## 五、GitHub 保存什么 / 不保存什么

**保存：** 目录结构、README、项目控制文档、我们自己的分析 / 报告 / Skill / 脚本、创作中的作品文本（自有版权）。

**不保存：** `01_原始素材` 下的任何原始格式文件、`.env` / 密钥 / credentials、大型二进制工具（如 pandoc.exe）、缓存与临时日志。

## 六、原始资料保护

`01_原始素材` 中的原始文件**不得覆盖、修改、误删、全量解压或批量格式转换**。它们以本地文件为准，项目只引用其元数据（路径、SHA256 等），不改动本体。

## 七、两类作品各自主要研究什么

**网络小说**主要研究：阅读驱动力、期待与兑现、爽点、悬念、节奏、连载结构、长篇留存、商业叙事能力。

**优秀文学作品**主要研究：人性、人物复杂性、情感、主题、语言、意象、深层叙事、结构、文学表达。

两类作品都可以优秀，也都可能存在缺点。目标是吸收各自真正有效的能力，而不是机械模仿。网络小说与世界文学不存在简单的“高低级关系”。

## 八、“原著蒸馏” vs “写作知识库”

- `02_原著蒸馏`：从**某一部具体作品**提炼的分析（这部书的结构、人物、节奏……），依附于作品本身。
- `04_写作知识库`：从多部作品中抽离出来的**跨作品、可复用**的写作知识 / 方法 / 规律。

前者是“就书论书”的分析沉淀，后者是“去作品化”的方法沉淀。

## 九、作品工程是终点

`03_作品工程` 是最终创作发生的位置：设定、大纲、人物、章节、正文都在这里。前面所有环节（素材、蒸馏、知识库）都服务于这里产出我们自己的长篇作品。

## 十、工作台建设原则

AI-write 的目标不是从现有 GitHub 项目或 Skill 中选出一个“冠军”，也不是把多个项目简单拼接起来，而是形成**我们自己的、统一的 AI 写作工作台**。

- **评估能力，不评项目输赢。** Benchmark 的主要对象应是具体能力、机制和工作流；只有解决同一问题时才比较优劣，互补能力可以同时保留。
- **外部项目是参考来源，不是最终架构。** 可吸收其有效思想、方法和工程经验，但要结合证据、许可证、维护成本与本项目需求决定保留、改造、独立实现或舍弃。
- **以真实创作价值为最终标准。** 能否帮助作者设计、写作、诊断、修订和维持长篇一致性，比术语数量、格式完整或单次模型评分更重要。
- **作者评实际效果，不负责学习内部术语。** Skill、证据、许可证、重复度等方法判断由 Controller / Benchmark 处理；需要作者参与时，应转换成具体小说问题、实际方案或前后对照，让作者判断“是否更想写、是否更自然、是否真有帮助”。
- **先验证，再沉淀。** 未经证据核验、跨样本验证或人工判断的机制，不直接进入正式知识库与生产 Skill。
- **最终统一。** 通过研究得到的能力应逐步收敛到 AI-write 自己的数据结构、上下文组织、知识库、Skill 与创作流程中，避免形成彼此割裂的外部项目“拼盘”。
