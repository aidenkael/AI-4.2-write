## G4 唯一核心目标

证明 AI-write 可以在**不依赖聊天记忆、不把整个项目/全部 BKP 塞给模型、不自动替作者做重大创作决定**的前提下，把：

```text
作者意图
+ 当前作品状态 / Canon
+ 当前创作焦点
+ 希望读者经历什么
+ 少量相关 BKP 知识
```

编译成小而相关、可追溯的创作上下文，并进一步：

```text
1～3 个真正有差异的创作方向
→ 说明依据 / 风险 / 冲突 / 边界
→ 作者选择 / 修改 / 全部拒绝
→ 只在作者确认后更新计划 / Story State
```

G4 不负责证明正文质量；Writer、Reader/Critic/Editor 完整生产闭环留给后续 Gate。

## G4 五种概念工件

1. **Author Intent**：作品方向、作者当前最在意/不想要的东西、Current Focus；
2. **Story State / Canon**：原创作品权威事实与当前状态；
3. **Creation Brief**：当前创作问题、人物欲望/阻力、读者目标、硬约束与自由空间；
4. **Context Package**：从权威状态 + KnowledgeRetrieve 少量 BKP Hit 派生的小上下文；
5. **Decision Record / State Diff**：作者确认后的决策理由和状态变化。

**BKP 参考知识与原创 Canon 必须严格分离。**

G4-A 已把这五类工件的最小字段、authority/derived 边界、revision/stale 规则、作者确认门和 State Diff 写回协议草案：`06_工作区/G4A_最小创作合同_v0.1.md`。

## G4-A 已确认的最小语义边界

- **Author Intent** 是作者方向权威；AI 可提议，只有作者确认才能形成新 revision。
- **Story State / Canon** 是原创作品权威状态；BKP、AI 推演和 Context Package 都不能直接写入。
- **approved_plan ≠ Canon**：已确认未来计划仍可被作者推翻，但必须留 Decision / Diff 记录。
- **Creation Brief** 是当前任务合同；必须显式记录 AI 自己补出的 assumptions，不能把推断伪装成作者要求。
- **Context Package** 是可重建派生层；依赖的 intent/state/brief revision 改变后即 STALE。
- **Decision Record** 记录方案与作者最终取舍；作者 `reject_all` 时不得改变 Story State。
- **State Diff** 只能基于当前 `state_rev` 应用；旧 Diff 不得覆盖新状态。
- 所有真正写回 Story State 的变化都应能追溯到作者确认的 `decision_id`。
