# AI-write 项目阶段门禁

> 用途：约束跨会话、跨 Agent 的执行顺序，防止对话变长后偏离已确认路线。  
> 本文件只记录“当前阶段允许做什么、完成条件是什么、下一阶段什么时候才能开始”。  
> 若本文件与单次 Agent 临时建议冲突，以用户最新明确确认 + 本文件当前门禁为准；不得由 Agent 自行跳阶段。  
> 首次建立：2026-08-10；最近重大更新：2026-08-11（G3-C 最小原型完成）。

## 一、执行前必读顺序

任何进入仓库的新 Agent / Controller，在开始实质工作前必须按顺序确认：

1. `00_项目控制/README_目录使用说明.md` —— 项目目标与目录权威说明；
2. `AGENTS.md` —— 长期执行、Git、本地保护、知识固化规则；
3. `AI-write_长期开发手册.md` —— 长期架构、开发路线、里子/面子与闭环规则；
4. `00_项目控制/当前工作索引.md` —— 当前状态入口；
5. `00_项目控制/项目推进记忆.md` —— 跨阶段关键决策；
6. 本文件 —— 当前允许动作与退出条件；
7. 本次任务涉及专项时，再读取对应 STATUS / 协议。

单次聊天摘要、Agent 自己的建议、旧计划不得覆盖以上长期文件和用户最新明确确认。

## 二、任务开始时必须先声明四件事

Agent 开始执行前，先用简短文字确认：

- 当前门禁阶段；
- 本次唯一主目标；
- 本次明确禁止触碰的范围；
- 本阶段退出条件中，本次准备完成哪一项。

如果无法从仓库确定这四项，先停止并汇报，不自行推断新路线。

## 三、当前门禁：G3｜跨书知识库与创作任务检索

> **建立日期：2026-08-11**  
> **对应长期路线：Phase D｜跨书知识库与检索**  
> **当前状态：G3 已正式建立，G3-C 最小原型已完成。**

G0（全局能力地图 v0.2）、G1（最小 BookDistill v0.1）、G2（原著蒸馏体系收口与 BookDistill vNext 前置设计）均已完成并由作者确认退出。

### G3 说明

这是重新定义后的新 G3。旧版"G3 = 直接正式作品工程/正式创作"的路线已经废止，不得恢复。

### G3 唯一核心目标

不是"做一个大型 RAG 系统"。

真正目标是证明：**多个 BKP 可以共同存在；当出现一个真实创作问题时，AI-write 能从它们中找到少量真正相关、可追溯、有边界的知识，而作者不需要记住哪本书、哪个 Pattern。**

核心链路：

```text
真实创作问题
→ 理解创作意图
→ 从多个 BKP 找候选知识
→ 相关性筛选 / 去重 / 排序
→ 保留 evidence / scope / boundary
→ 输出少量可供后续 Planner / Writer / Critic 使用的知识
```

### G3 必须坚持的原则

1. **Borrow-first。** 正式实现前先重新审查已有成熟 Retrieval / RAG / KG / Context selection 方案。重点优先复查长期手册已经记录的候选（AI-Novel-Writing-Assistant、InkOS、graphify-novel、NovelForge、story-skills 等）。不要无限搜索。
2. **不自研底层搜索引擎。** AI-write 自研集中在：创作任务表达、BKP 知识标签/索引、少量相关知识选择、来源/边界/知识等级保留、结果交给未来 Context Compiler。
3. **先简单检索，后复杂基础设施。** G3 初期必须允许 Markdown / JSON + 简单索引 + Agent 语义判断。只有真实测试证明简单方案不足，才升级。

### G3 内部子阶段

**G3-A：成熟方案复查**

对 Retrieval / RAG / KG / Context selection 相关成熟方案做一轮有边界的复查。重点候选：AI-Novel-Writing-Assistant、InkOS、graphify-novel、NovelForge、story-skills，以及当前候选池中 Retrieval / Context Compiler 相关项目。产出"直接借 / 适配后用 / 只借方法 / 不适合 / 真正缺口"清单。不无限搜索。

**G3-B：定义最小跨书知识入口 / 检索合同**

基于 G3-A 结论，定义 AI-write 的最小跨书知识统一入口与检索合同：多 BKP 如何并存、检索输入/输出格式、知识等级与来源如何保留、scope/boundary 如何不丢失。

**G3-C：用两个现有 BKP 做最小检索原型**

用 `book_0038 一九八四` 和 `book_0065 三体` 的正式 BKP 构建最小检索原型。允许 Markdown / JSON + 简单索引 + Agent 语义判断。

**G3-D：真实创作问题验证**

给出若干真实创作问题，验证系统能跨书找到相关知识，并满足退出条件中的全部要求。

**G3 收口判断**

根据 G3-D 验证结果，判断是否满足全部退出条件，提交作者验收。

### G3 最小退出条件

1. 《一九八四》和《三体》两个正式 BKP 可以同时进入统一知识入口；
2. 给出若干真实创作问题时，系统能跨书找到相关知识；
3. 返回结果数量受控，不把整个 BKP 塞给模型；
4. 返回知识可以追溯到：哪本书、哪条 Observation / Inference / Pattern、必要的原始 evidence；
5. Scope / Boundary / Counterevidence 不在检索过程中丢失；
6. 单书 Pattern 不会因为跨书检索自动升级成写作规则；
7. 至少验证三类问题：
   - 明显只与一本书相关的问题；
   - 两本书都可能提供帮助的问题；
   - BKP 中没有可靠答案的问题；
8. 能证明未来 Planner / Writer / Critic 可以拿到"小而相关"的知识包；
9. 项目控制文档和长期开发手册同步；
10. 用户验收后才能退出 G3。

### G3 明确禁止事项

- 不批量蒸馏更多小说来"丰富数据库"；
- 不跑第三本书，只为测试 Retrieval；
- 不直接进入正式小说；
- 不建立大型 KG；
- 不因为"以后可能需要"预先开发复杂向量数据库；
- 不做完整 Context Compiler；
- 不做 Writer / Planner / Critic；
- 不开发 UI；
- 不把检索频率或相似度直接当成写作规律；
- 不把两本书出现相似模式就自动升级成 Cross-book Pattern；
- 不修改已稳定的 BookDistill，除非 Retrieval 真实暴露 BKP 阻塞性缺陷；
- 不无限扩大 GitHub 搜索；
- 不自动退出 G3。

## 六、禁止“顺手扩展”

每次 Agent 任务只推进当前门禁中的一个明确子目标。

发现其他问题时：

- 可以记录；
- 可以提出下一步建议；
- 不得因为“顺手”“以后会用到”“架构更完整”直接扩大任务。

任何跨门禁动作、重大目录变化、新 Benchmark、批量处理或新架构建设，都需要用户明确授权。

## 七、阶段收口同步要求

每次 Gate closeout 或用户确认重大架构变化后，必须检查并同步：

1. `AI-write_长期开发手册.md`（含 AUTO 当前状态/下一步/风险）；
2. `00_项目控制/当前工作索引.md`；
3. `00_项目控制/项目推进记忆.md`；
4. 本文件；
5. `AGENTS.md`（仅长期规则变化时）；
6. 相关 STATUS / provenance。

然后 commit、报告 SHA；**没有用户明确确认，不自动切下一 Gate。**
