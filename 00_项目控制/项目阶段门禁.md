# AI-write 项目阶段门禁

> 用途：约束跨会话、跨 Agent 的执行顺序，防止对话变长后偏离已确认路线。  
> 本文件只记录“当前阶段允许做什么、完成条件是什么、下一阶段什么时候才能开始”。  
> 若本文件与单次 Agent 临时建议冲突，以用户最新明确确认 + 本文件当前门禁为准；不得由 Agent 自行跳阶段。  
> 首次建立：2026-08-10；最近重大更新：2026-08-11。

## 一、执行前必读顺序

任何进入仓库的新 Agent / Controller，在开始实质工作前必须按顺序确认：

1. `00_项目控制/README_目录使用说明.md` —— 项目目标与目录权威说明；
2. `AGENTS.md` —— 长期执行、Git、本地保护、知识固化规则；
3. `AI-write_长期开发手册.md` —— 长期架构、开发路线、里子/面子与闭环规则；
4. `00_项目控制/当前工作索引.md` —— 当前状态入口；
5. `00_项目控制/项目推进记忆.md` —— 跨阶段关键决策；
6. 本文件 —— 当前允许动作与退出条件；
7. 本次任务涉及专项时，再读取对应 STATUS / 协议。

单次聊天摘要、Agent 自己的建议、旧计划不得覆盖以上长期文件和用户最新明确确认。

## 二、任务开始时必须先声明四件事

Agent 开始执行前，先用简短文字确认：

- 当前门禁阶段；
- 本次唯一主目标；
- 本次明确禁止触碰的范围；
- 本阶段退出条件中，本次准备完成哪一项。

如果无法从仓库确定这四项，先停止并汇报，不自行推断新路线。

## 三、当前门禁：G2｜原著蒸馏体系收口与 BookDistill vNext 前置设计

G0（全局能力地图 v0.2）与 G1（最小 BookDistill v0.1）均已完成并由用户确认退出。

G2 原目标是用 1–2 部不同类型真实作品验证 BookDistill 的跨书价值。现在两本真实样本已经足够暴露关键事实：

- `book_0038 一九八四` 与 `book_0065 三体` 均可完整蒸馏；
- evidence-first、来源追溯、章节/行号机械校验是有效地基；
- 但 `model.md + mechanisms.md` 作为主要作者综合层压缩过强，无法代表一本长篇所有值得长期保存的写作知识；
- 当前方案不适合直接批量蒸馏几十本，也不应沿旧路线直接进入正式创作。

因此用户已确认：**G2 在退出前先完成原著知识资产与 vNext 方案收口。**

### G2 唯一目标

在不扩大规模化蒸馏的前提下，完成以下战略收口：

1. 对新版完整工作台所需能力做一轮有边界 GitHub 再审查；
2. 明确每一能力层“直接借 / 改造 / 只借方法 / 不适合 / 真正自研缺口”；
3. 定义 Book Knowledge Package（BKP）的候选协议与多层知识粒度；
4. 定义 BookProfile 的位置：全维度基础蒸馏之后生成，用于分配后续专项预算；
5. 明确一本书 `1 次基础 + 1～N 次专项` 的自适应蒸馏逻辑；
6. 定义 BookDistill vNext 的最小工作流；
7. 明确单书知识不得直接固化为普遍写作定律。

### G2 核心知识等级

所有 Agent 必须区分：

`Source Evidence → Observation → Pattern Hypothesis → Cross-book Pattern → Creation-tested Heuristic → Production Rule`

单本作品内归纳默认停留在 Observation / Pattern Hypothesis；不得直接进入 Production Rule。

### G2 允许范围

1. 复查现有 GitHub 候选；
2. 围绕以下能力层做一次**有边界的新搜索**：
   - 原著知识化 / 文学分析；
   - Story Bible / Canon；
   - 长篇规划；
   - Writer；
   - Memory；
   - Retrieval / RAG / KG；
   - Continuity；
   - Reader / Critic / Editor；
   - Context compilation；
   - Controller / author control；
3. 每层只找足够成熟、差异清晰的少量方案，达到覆盖后停止搜索；
4. 设计 BKP / BookProfile / BookDistill vNext 协议；
5. 用现有《一九八四》《三体》产物做只读对照、回归或 schema 检查；
6. 如两本样本确实无法验证某个关键维度，可先提出第三本样本建议，但**不得未经用户明确授权直接运行**；
7. 对已有文档做必要状态对齐。

### G2 禁止范围

- 自动蒸馏第三本；
- 批量蒸馏 60/141 本素材；
- 冻结最终 BKP schema；
- 把《一九八四》15 条、《三体》17 条机制写成 AI-write 生产规则；
- 重启 B02 / B09；
- 修改 SourcePrepare（除非出现明确输入阻塞并经授权）；
- 先建设大型 RAG/KG/多 Agent 平台；
- 开发完整独立软件 / UI；
- 进入正式长篇作品主线；
- 修改能力地图成熟度为 M5；
- 无限扩大 GitHub 搜索；
- 为了赶 Gate 跳过成熟方案复查、BKP 协议或用户确认。

### G2 最小退出条件

G2 只有同时满足以下条件，才可以提交“请求用户确认退出”的报告：

1. 新版能力层 GitHub 审查已达到足够覆盖，且明确哪些借、哪些改、哪些真需要自研；
2. BKP 候选协议已经能容纳至少《一九八四》《三体》两种明显不同的作品，而不强行压平；
3. BookProfile 已定义为“全维度基础蒸馏后的动态画像”，并有价值/证据量/置信度/不确定性/专项预算规则；
4. BookDistill vNext 工作流已经明确：基础蒸馏 → Profile → 1～N 专项 → 交叉验证/去重 → BKP；
5. 已写明写作时主要检索 BKP，不日常重新蒸馏原著；
6. 已写明知识等级与跨书/真实创作验证边界；
7. 根目录长期手册、当前索引、项目记忆、本门禁保持一致；
8. 用户完成审阅并明确确认 G2 可退出。

**满足 1–7 仍不能自动进入下一 Gate。必须等待用户第 8 项确认。**

## 五、后续 Gate 不预设为“直接正式创作”

旧文档曾把 G3 直接定义为真实作品工程最小闭环。该路线现在**不再自动成立**。

当前长期战略路线见根目录 `AI-write_长期开发手册.md`：

`能力层 GitHub 复查 → BKP/BookProfile → BookDistill vNext → 跨书知识与检索 → 创作核心后台 → 创作沙盒 → Production v1.0 → 正式长篇`

G2 退出时，再由用户根据当时成果定义下一 Gate。Agent 不得自行沿用旧 G3 名称或内容。

## 六、禁止“顺手扩展”

每次 Agent 任务只推进当前门禁中的一个明确子目标。

发现其他问题时：

- 可以记录；
- 可以提出下一步建议；
- 不得因为“顺手”“以后会用到”“架构更完整”直接扩大任务。

任何跨门禁动作、重大目录变化、新 Benchmark、批量处理或新架构建设，都需要用户明确授权。

## 七、阶段收口同步要求

每次 Gate closeout 或用户确认重大架构变化后，必须检查并同步：

1. `AI-write_长期开发手册.md`（含 AUTO 当前状态/下一步/风险）；
2. `00_项目控制/当前工作索引.md`；
3. `00_项目控制/项目推进记忆.md`；
4. 本文件；
5. `AGENTS.md`（仅长期规则变化时）；
6. 相关 STATUS / provenance。

然后 commit、报告 SHA；**没有用户明确确认，不自动切下一 Gate。**
