# AI-write 项目阶段门禁

> 当前 Gate、允许动作、退出条件和禁止范围的权威入口。更新时间：2026-08-13。

## 1. 当前 Gate

**G5｜正文诊断与修订最小闭环：ACTIVE / G5-C。**

G0–G4 已关闭。G5-A/B 已完成；当前进入 G5-C。

## 2. G5 唯一目标

验证一条小而真实的正文闭环：

`当前状态 + 新 Context → 一次性正文 → 独立 Reader/Critic/Editor 诊断 → 作者自然语言反馈 → Controller 三角校验 → 修订 → 作者判断`

重点不是证明某个 Writer 最强，而是证明系统能帮助作者判断，而不是只把作者的话翻译成修改命令。

## 3. 作者反馈边界

系统必须区分：

1. **目标/硬约束**：作者想要什么、什么不能牺牲；
2. **症状/感觉**：作者觉得哪里平、拖、不像、没劲；
3. **原因判断**：作者认为为什么会这样；
4. **修法建议**：作者建议删、加、改、换。

目标/硬约束与重大最终取舍由作者控制。症状是强信号，但原因判断与修法建议默认只是待验证假设。

AI 可以同意，也可以基于正文证据、Reader/Critic/Editor、角色/连续性和 BKP 明确提出不同诊断。AI 诊断同样可能错；冲突时保留依据、置信度和替代解释。

## 6. G5-C 当前规则

- 作者先直接阅读 `g5b/draft_v1.md`，只说真实感觉，不要求正确诊断；
- 在作者本轮反馈形成前，不额外展开完整 AI 诊断来引导其判断；
- Controller 收到反馈后再与既有独立诊断和正文 evidence 做三角校验；
- 可以 agree / partly_agree / disagree / uncertain；
- 若不同意作者原因或修法，必须说明证据、风险和替代方向；
- 修订只针对确认值得处理的问题，不为了“证明 AI 更专业”故意反对作者；
- 修订稿仍是 sandbox/noncanon，作者接受前不产生 accepted_text；
- 不修改 Story State；
- 不自动进入 G5-D。

## 7. G5 总退出条件

G5 closeout 前至少需要证明：

- AI 能先于作者反馈独立诊断正文；
- 作者反馈可以被正确拆成目标/症状/原因/修法；
- 当作者原因判断或修法与文本证据冲突时，Controller 可以有依据地不同意并给替代方案；
- 当 AI 多路诊断冲突时，不强造共识；
- 修订确实针对被确认的问题；
- 作者最终可以接受、拒绝或继续修改；
- 若正文被接受，明确事实的最小 state settlement 可追溯且不偷渡推断；
- G5 不扩成完整生产平台。

## 8. 当前禁止

- 不要求作者先给“正确诊断”；
- 不机械执行作者修法；
- 不把 AI/Reader/Critic/Editor 当客观裁判；
- 不使用正式长篇作为实验；
- 不一次实现完整 Writer/Reader/Critic/Editor/Controller；
- 不升级 Retrieval/RAG/KG；
- 不批量蒸馏新书；
- 不开发 UI、大型数据库、多 Agent 平台；
- 不自动进入 G5-D/E。

## 9. Git 安全

无明确授权禁止：`reset / restore / clean / force push / rebase / merge`。

历史 local dirty / untracked / `stash@{0}` 先识别再处理；普通同步不建立无意义长期分支。
