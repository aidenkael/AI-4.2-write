# AI-write 项目阶段门禁

> 当前 Gate、允许动作、退出条件和禁止范围的权威入口。更新时间：2026-08-13。

## 1. 当前 Gate

**原著知识提取与蒸馏：ACTIVE。**

G0–G4 已关闭。G5｜正文诊断与修订最小闭环：**PAUSED**，不作为当前主线。

## 2. 唯一目标

把“原著 → 可长期调用的 BKP”这条知识生产链研究清楚、跑稳定：

`SourcePrepare → 初步作品识别/BookProfile → 多视角直接原著 Discovery → 按需 Deep Dive → BookDistill 总编辑收敛 → BKP → Retrieval`

当前不要求把它压缩成一个 Skill、一次作者操作或固定次数的蒸馏流程。

## 3. 方法边界

- SourcePrepare 负责作品身份、来源/版本、完整性、章节和标准输入，不做文学判断；
- 初步 BookProfile 负责导航：先建立结构、阶段、reader promise、显著/潜在强项和不确定项；它可以后续修订，不能提前过滤未知价值；
- 重要 Discovery 镜头应直接读或回查原著，不只消费二手摘要；
- 默认已有两个互补镜头：长篇运行/读者动力，Reader/Page Craft；这是默认观察方向，不是固定蒸馏次数，也不是永久固定 Skill 数量；
- Base Scan 的 MAP / Evidence / Observation / Boundary 是阅读中的证据记录层；
- Deep Dive 只按真实高价值问题触发，数量不冻结；
- BookDistill 负责回源核证、去重、跨尺度组合、Observation/Inference 分层、scope/boundary/counterevidence/confidence 和 BKP 收敛；
- 原著始终是最高事实源；单书 BKP 最高默认到 Work-specific Pattern。

## 4. 当前完成条件

当前 Gate 只要求证明：

1. 一部此前未蒸馏的新书可以被可靠识别并形成可用的初步作品导航；
2. 多个互补视角能直接基于原著提取出有证据、非重复、跨尺度的高价值观察；
3. 需要时能做专项 Deep Dive，而不是机械跑固定次数；
4. BookDistill 能把候选知识收敛成克制、可追溯、可检索的 BKP；
5. 最终能明确说明这次提取得好的部分、仍可能遗漏的部分和下一步真实缺口。

不把一键入口、统一 orchestrator、固定 Pass 数量、批量流水线、UI 或正式写作作为当前退出条件。

## 5. 当前允许

- 改造现有 SourcePrepare / BookDistill / BKP 流程；
- 从现有候选池成熟项目直接借用拆文、分块、增量扫描、证据回溯、Reader/Craft、Developmental Editing 等实现与方法；
- 根据真实原著需要增加、合并或调整观察 Pass / Skill；
- 做必要的断点恢复、章节边界和 token 预算工程改进；
- 选一部新书做真实完整研究。

当前私人项目中，许可证只做 provenance 记录，不作为技术路线阻塞。

## 6. 当前禁止

- 不继续 G5 正文诊断实验；
- 不要求作者评价测试小说；
- 不把操作简化反过来变成方法限制；
- 不固定每本书相同的 Discovery / Deep Dive 数量；
- 不为了单一案例扩张永久 Schema；
- 不升级 RAG/KG；
- 不开发 Writer、UI、大型数据库或多 Agent 平台；
- 不批量蒸馏全部素材。

## 7. 作者交互

作者可以接受当前存在多个步骤或多个 Agent/Skill。作者侧简化是后续产品化目标，不是当前研究前提。

只有来源 `REVIEW/FAIL`、作品身份无法确定或重大文学解释确实无法由证据裁决时，才需要作者中途参与。

## 8. Git 安全

无明确授权禁止：`reset / restore / clean / force push / rebase / merge`。

历史 local dirty / untracked / `stash@{0}` 先识别再处理；普通同步不建立无意义长期分支。

## 9. 防跑偏

> **当前不是研究怎样把流程压成一个按钮，而是研究怎样真正从原著中提取、核证并保存有长期创作价值的知识。**
