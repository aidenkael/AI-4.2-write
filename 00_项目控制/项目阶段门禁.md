# AI-write 项目阶段门禁

> 用途：约束跨会话、跨 Agent 的执行顺序，防止对话变长后偏离已确认路线。
> 本文件只记录“当前阶段允许做什么、完成条件是什么、下一阶段什么时候才能开始”。
> 若本文件与单次 Agent 临时建议冲突，以用户最新明确确认 + 本文件当前门禁为准；不得由 Agent 自行跳阶段。
> 首次建立：2026-08-10

## 一、执行前必读顺序

任何进入仓库的新 Agent / Controller，在开始实质工作前必须按顺序确认：

1. `00_项目控制/README_目录使用说明.md` —— 项目目标与目录权威说明；
2. `AGENTS.md` —— 长期执行、许可证、Git 与本地保护规则；
3. `00_项目控制/当前工作索引.md` —— 当前状态入口；
4. `00_项目控制/项目推进记忆.md` —— 跨阶段关键决策；
5. 本文件 `00_项目控制/项目阶段门禁.md` —— 当前允许动作与退出条件；
6. 本次任务涉及专项时，再读取对应 STATUS / 协议。

单次聊天摘要、Agent 自己的建议、旧计划不得覆盖以上长期文件和用户最新明确确认。

## 二、任务开始时必须先声明四件事

Agent 开始执行前，先用简短文字确认：

- 当前门禁阶段；
- 本次唯一主目标；
- 本次明确禁止触碰的范围；
- 本阶段退出条件中，本次准备完成哪一项。

如果无法从仓库确定这四项，先停止并汇报，不自行推断新路线。

## 三、当前门禁：G0｜全局能力地图 v0.2 收口

当前项目**尚未进入 BookDistill 实现 / 正式原著蒸馏阶段**。

本阶段目标不是重新开启大量 Benchmark，而是把此前研究结果、候选项目和空白能力整理成一张足够可靠的全局导航图，明确“已有能力、证据等级、候选来源、是否实测、许可证边界、下一次什么时候需要验证”。

### G0 必须完成的交付

1. 逐项复核 C01–C20：
   - 当前成熟度；
   - 已有证据；
   - 主要候选/来源；
   - `实际比较状态`：正式实测 / 轻量实测 / 仅架构或代码审阅 / 未实测；
   - 已知边界与副作用；
   - 下一次触发验证的真实问题。

2. 建立“高价值上游 × 能力覆盖”矩阵，至少覆盖当前正式/重点候选：
   - oh-story；
   - ani-book-skill；
   - Apodictic；
   - creative-writing-skills；
   - NovelClaw；
   - InkOS；
   - NovelForge；
   - AI-Novel-Writing-Assistant；
   - AuthorAgent；
   - autonovel；
   - 以及候选池中仍被保留、且确有独特价值的项目。

3. 每个重点项目必须区分：
   - 出现在候选池 ≠ 已经比较过；
   - 未参加某个 Benchmark ≠ 被淘汰；
   - 许可证/授权有额外义务 ≠ 当前私人研究阶段自动排除；
   - 无明确许可证时，只能研究公开结构/行为，不能把受版权保护代码或 Prompt 直接吸收进核心。

4. 对 NovelForge、AI-Novel-Writing-Assistant、InkOS、NovelClaw、AuthorAgent 等工程型候选，优先比较其真正擅长的 C17/C20 等能力：
   - Canon / Memory；
   - 上下文选择与编译；
   - 状态写回；
   - 恢复/断点续作；
   - 人工确认边界；
   - 长篇状态压缩与一致性。
   不为了“补参赛”把它们塞进不适合的情绪正文比赛。

5. 只有在矩阵明确发现重要能力空白后，才允许做一次有限 GitHub 查漏补缺；不得无目的扩充候选池。

6. 最终产物：
   - `AI-write_全局能力地图_v0.2.md`；
   - 更新后的 GitHub 候选能力路由（版本按实际修订决定）；
   - `当前工作索引.md` 与 `项目推进记忆.md` 同步当前阶段状态。

### G0 明确禁止

在 G0 完成并由用户确认前，不得：

- 实现 BookDistill；
- 启动正式原著蒸馏；
- 因为已有 SourcePrepare PASS 输入就跳过地图收口；
- 重启 B02 / B09；
- 按 C01–C20 顺序逐项开启重型 Benchmark；
- 新建大型多 Agent / RAG / 图数据库架构；
- 因许可证标签自动删除高价值候选；
- 将“候选池中存在”误写成“已经实测验证”。

## 四、下一门禁：G1｜最小 BookDistill v0.1

只有 G0 完成并由用户确认后，才进入 G1。

G1 的目标是最小可用，而不是完整蒸馏平台：

`SourcePrepare PASS → BookDistill → 02_原著蒸馏`

优先解决：

- 能完整读取一本书；
- 证据可追溯；
- fact / inference / hypothesis 分离；
- 输出对作者理解结构、人物、节奏、场景、信息控制和可迁移技法有直接帮助；
- 避免过重 schema、知识图谱和报告工程。

SourcePrepare 本地已经存在可用 PASS 输入，因此进入 G1 后默认不需要先重新跑全量 SourcePrepare。

## 五、后续门禁

### G2｜1–2 部真实蒸馏

只蒸馏少量与真实创作目标相关的作品，用实际作者体验判断 BookDistill 是否有价值。

### G3｜真实作品工程最小闭环

进入：

`设定/人物 → 大纲 → 场景 → 正文 → 连续性 → 诊断修订`

之后由真实创作瓶颈回到能力地图定位问题，再做最小验证；只有高价值、证据矛盾或错误固化代价高时，才升级严格 Benchmark。

## 六、禁止“顺手扩展”

每次 Agent 任务原则上只推进当前门禁中的一个明确子目标。

发现其他问题时：

- 可以记录；
- 可以提出下一步建议；
- 不得因为“顺手”“以后会用到”“架构更完整”而直接扩大任务。

任何跨门禁动作、重大目录变化、新 Benchmark、批量处理或新架构建设，都需要用户明确授权。
