# AI-write 项目阶段门禁

> 用途：约束跨会话、跨 Agent 的执行顺序，防止对话变长后偏离已确认路线。
> 本文件只记录“当前阶段允许做什么、完成条件是什么、下一阶段什么时候才能开始”。
> 若本文件与单次 Agent 临时建议冲突，以用户最新明确确认 + 本文件当前门禁为准；不得由 Agent 自行跳阶段。
> 首次建立：2026-08-10

## 一、执行前必读顺序

任何进入仓库的新 Agent / Controller，在开始实质工作前必须按顺序确认：

1. `00_项目控制/README_目录使用说明.md` —— 项目目标与目录权威说明；
2. `AGENTS.md` —— 长期执行、许可证、Git 与本地保护规则；
3. `00_项目控制/当前工作索引.md` —— 当前状态入口；
4. `00_项目控制/项目推进记忆.md` —— 跨阶段关键决策；
5. 本文件 `00_项目控制/项目阶段门禁.md` —— 当前允许动作与退出条件；
6. 本次任务涉及专项时，再读取对应 STATUS / 协议。

单次聊天摘要、Agent 自己的建议、旧计划不得覆盖以上长期文件和用户最新明确确认。

## 二、任务开始时必须先声明四件事

Agent 开始执行前，先用简短文字确认：

- 当前门禁阶段；
- 本次唯一主目标；
- 本次明确禁止触碰的范围；
- 本阶段退出条件中，本次准备完成哪一项。

如果无法从仓库确定这四项，先停止并汇报，不自行推断新路线。

## 三、当前门禁：G2｜1–2 部真实原著蒸馏

G0（全局能力地图 v0.2 收口）与 G1（最小 BookDistill v0.1）均已完成并由用户确认退出。
当前项目进入 G2：用少量不同类型真实作品验证 BookDistill 的跨书价值。

### G2 唯一目标

用 1–2 部不同类型真实作品判断：

- BookDistill 是否能跨书稳定工作；
- model.md 是否仍然有作者价值；
- mechanisms 是否能体现作品差异；
- 是否出现大量空泛、模板化、AI 总结腔；
- 哪些机制以后值得进入真实创作调用。

### G2 不是

- 批量蒸馏全部素材；
- 建完整知识库；
- 建 RAG；
- 建图数据库；
- 建多 Agent 平台；
- 连续跑大型 Benchmark。

### G2 允许范围

1. 在**后续单独任务**中决定选择哪 1–2 部具体作品；
2. 对所选作品运行 BookDistill（validate / prepare / assemble + 作者综合层）；
3. 跨书对比 model / mechanisms 的差异与稳定性；
4. 记录作者对每本书蒸馏产物的实际判断；
5. 根据真实结果做少量必要修正。

### G2 禁止范围（本阶段不提前决定）

- 在完成选书前直接运行未确认作品 / 开始第二本蒸馏（选书本身由 G2 内的单独选书任务确定，
  不再列为 G2 禁止事项）；
- 搜索新 GitHub；
- 新 Benchmark；
- 重启 B02 / B09；
- 修改 SourcePrepare；
- 建新架构（RAG / 图数据库 / 多 Agent / DB）；
- 建知识库；
- 进入 G3；
- 修改能力地图成熟度；
- 把 BookDistill 标记为 M5。

### G2 最小退出条件

作者完成 1–2 部不同类型真实作品的蒸馏与判断，确认 BookDistill 是否值得进入真实创作调用；
G2 完成后**仍不能自动进入 G3**，必须由用户确认。

## 四、历史门禁

### G0：全局能力地图 v0.2 收口 —— 已完成并由用户确认退出

- 产出 `AI-write_全局能力地图_v0.2.md` 与 `GitHub候选池_能力路由_v0.2.md`；
- 候选来源覆盖 20/20；直接实证覆盖 5/20；生产固化（M5）0/20。

### G1：最小 BookDistill v0.1 —— 完成并由用户确认退出

**BookDistill v0.1.1 首本 pilot 通过 G1 最小退出条件**：

1. 有真实可运行 BookDistill（validate / prepare / assemble，含 source snapshot 与行号越界校验）；
2. 能消费 SourcePrepare PASS；
3. 完整处理 1 部真实作品（`book_0038 一九八四`）；
4. 输出可追溯（证据引用到原始章节/行号）；
5. 区分：事实 / 推断 / 可迁移机制 / 边界与不确定性；
6. 作者已实际查看；
7. 不要求生产级自动化。

作者审阅结论（2026-08-11）：已实际阅读 model.md / mechanisms.md，整体认为总结不错、
能够理解、具有启发；作为新手作者，目前无法可靠判断 15 条机制是否真的能提升小说质量。
因此：**"作者可读性 / 可理解性"通过 G1**；"机制是否真正提升创作效果"不在 G1 强行判定，
延后到真实作品创作中验证。15 条机制未升级为已验证生产规则，BookDistill 未达到 M5。

## 五、后续门禁

### G3｜真实作品工程最小闭环

进入：

`设定/人物 → 大纲 → 场景 → 正文 → 连续性 → 诊断修订`

之后由真实创作瓶颈回到能力地图定位问题，再做最小验证；只有高价值、证据矛盾或错误固化代价高时，才升级严格 Benchmark。

## 六、禁止“顺手扩展”

每次 Agent 任务原则上只推进当前门禁中的一个明确子目标。

发现其他问题时：

- 可以记录；
- 可以提出下一步建议；
- 不得因为“顺手”“以后会用到”“架构更完整”而直接扩大任务。

任何跨门禁动作、重大目录变化、新 Benchmark、批量处理或新架构建设，都需要用户明确授权。
