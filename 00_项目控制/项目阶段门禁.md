## 1. 当前 Gate

**G4｜创作上下文与作者决策最小闭环：ACTIVE / G4-D。**

G4-A/B/C 已完成；G4-D 进行中；G4-E 未开始。

## 2. G4-D 唯一目标

用至少一次**真实作者自然语言反馈**验证：

`候选方向 → 作者接受 / 修改 / 拒绝 / 暂缓 → 系统解释 → Decision Record / State Diff → 合法写回`

重点不是让作者学会工作流，而是证明后台能从模糊表达中判断：什么是创作决定、什么只是偏好、什么仍有歧义、什么根本不该写状态。

## 4. 写回规则

- `choose / modify`：先形成 Decision Record；只有语义足够明确且确实需要长期状态变化时才生成 State Diff；
- `reject_all / defer`：记录动作即可，默认不改 Story State；
- 改未来场景方案属于 `creative_change`，只能基于真实 `author_decision`，且 `approved_plan ≠ Canon`；
- 没有已接受正文时不得制造 `accepted_text`；
- 有歧义时保持候选/询问，不猜作者意思；
- BKP / Context / 模拟输入均无 Canon 写入权；
- Diff 必须基于当前 `base_state_rev`，旧 Diff 不得覆盖新状态。

## 5. G4-D 最小完成条件

至少证明：

1. 作者可以不用固定命令，只说自然语言；
2. 系统能识别 choose / modify / reject_all / defer 中的真实意图；
3. 至少一次真实作者反馈能形成可追溯 Decision Record；
4. 若需要写回，Diff 分类正确且不污染 Canon；若不需要，则明确不写；
5. 模拟分支测试不能冒充真实 author authority；
6. 状态更新后 revision / source / trace 完整；
7. 作者改变旧计划时系统允许改变，不把 `approved_plan` 当 Canon；
8. G4-D 完成后只标记技术验证候选，等待作者确认是否进入 G4-E。

## 6. 当前禁止

- 自动替作者选方向；
- 要求作者填写 Decision Record / State Diff；
- 为了测试而强行修改 Story State；
- 用模拟作者输入写权威状态；
- 把未来计划写成已发生事实；
- 实现完整 Writer / Reader / Critic / Editor；
- 升级 Retrieval / RAG / KG；
- 批量蒸馏新书；
- 自动进入 G4-E。

## 7. Git 安全

无明确授权禁止：`reset / restore / clean / force push / rebase / merge`。

历史 local dirty / untracked / `stash@{0}` 不自动恢复或清理；本阶段不为此建立临时分支。

## 8. 防跑偏

**作者控制 ≠ 作者审批。** 作者应该只感知创作内容和自己的感觉；Decision Record、Diff、revision 和 authority 都是后台责任。
