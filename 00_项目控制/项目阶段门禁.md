# AI-write 项目阶段门禁

> 用途：约束跨会话、跨 Agent 的执行顺序，防止对话变长后偏离已确认路线。
> 本文件只记录“当前阶段允许做什么、完成条件是什么、下一阶段什么时候才能开始”。
> 若本文件与单次 Agent 临时建议冲突，以用户最新明确确认 + 本文件当前门禁为准；不得由 Agent 自行跳阶段。
> 首次建立：2026-08-10

## 一、执行前必读顺序

任何进入仓库的新 Agent / Controller，在开始实质工作前必须按顺序确认：

1. `00_项目控制/README_目录使用说明.md` —— 项目目标与目录权威说明；
2. `AGENTS.md` —— 长期执行、许可证、Git 与本地保护规则；
3. `00_项目控制/当前工作索引.md` —— 当前状态入口；
4. `00_项目控制/项目推进记忆.md` —— 跨阶段关键决策；
5. 本文件 `00_项目控制/项目阶段门禁.md` —— 当前允许动作与退出条件；
6. 本次任务涉及专项时，再读取对应 STATUS / 协议。

单次聊天摘要、Agent 自己的建议、旧计划不得覆盖以上长期文件和用户最新明确确认。

## 二、任务开始时必须先声明四件事

Agent 开始执行前，先用简短文字确认：

- 当前门禁阶段；
- 本次唯一主目标；
- 本次明确禁止触碰的范围；
- 本阶段退出条件中，本次准备完成哪一项。

如果无法从仓库确定这四项，先停止并汇报，不自行推断新路线。

## 三、当前门禁：G1｜最小 BookDistill v0.1

G0（全局能力地图 v0.2 收口）已由用户确认完成并退出。当前项目进入 BookDistill 最小实现阶段。

### G1 唯一目标

建立一个**最小、真实可运行**的 BookDistill v0.1：

- 消费现有 SourcePrepare PASS 输入；
- 产出第一份真正可供作者使用的原著蒸馏结果。

### G1 不追求

- 完整蒸馏平台；
- RAG；
- 知识图谱；
- 多 Agent 系统；
- 数据库；
- 批量处理全部原著；
- 一次解决 C01–C20；
- 新一轮大 Benchmark。

### G1 允许范围

1. 只读检查现有 SourcePrepare PASS 输入；
2. 检查旧分支已有 BookDistill 接口草案；
3. 选择性吸收接口设计，不整体 merge 旧分支；
4. 设计并实现最小 BookDistill v0.1；
5. 使用 1 部真实作品作为首个开发样本；
6. 产出真实蒸馏结果；
7. 根据真实结果做少量必要修正。

**优先开发样本：`book_0038 一九八四`**（原因：已确认 SourcePrepare PASS，full.md / chapters / metadata.json 可用，规模适合作为第一轮真实接口样本）。这只是当前开发选择，不是长期固定首选，不写成项目规则。

### G1 禁止范围

- 批量蒸馏 141 部素材；
- 同时蒸馏很多作品；
- 新建大规模 Benchmark；
- 重启 B02；
- 重启 B09；
- 为 15 个无直接实证能力逐项补测试；
- 搜索新 GitHub 项目；
- 构建大型 RAG；
- 构建知识图谱；
- 构建复杂数据库；
- 构建多 Agent 编排平台；
- 本地模型部署；
- 提前进入 `03_作品工程`；
- 把未经真实蒸馏验证的结果写入正式知识库。

### G1 最小退出条件

只有同时满足以下条件才允许结束 G1：

1. BookDistill v0.1 有真实可运行实现；
2. 能读取一个 SourcePrepare PASS 包；
3. 至少完整处理 1 部真实作品；
4. 输出内容可追溯到原始章节/范围；
5. 区分：事实 / 推断 / 可迁移机制 / 边界与不确定性；
6. 作者能够实际查看并判断蒸馏结果是否有用；
7. 不要求达到生产级自动化。

G1 完成后**仍不能自动进入 G2**，必须由用户确认。

## 五、后续门禁

### G2｜1–2 部真实蒸馏

只蒸馏少量与真实创作目标相关的作品，用实际作者体验判断 BookDistill 是否有价值。

### G3｜真实作品工程最小闭环

进入：

`设定/人物 → 大纲 → 场景 → 正文 → 连续性 → 诊断修订`

之后由真实创作瓶颈回到能力地图定位问题，再做最小验证；只有高价值、证据矛盾或错误固化代价高时，才升级严格 Benchmark。

## 六、禁止“顺手扩展”

每次 Agent 任务原则上只推进当前门禁中的一个明确子目标。

发现其他问题时：

- 可以记录；
- 可以提出下一步建议；
- 不得因为“顺手”“以后会用到”“架构更完整”而直接扩大任务。

任何跨门禁动作、重大目录变化、新 Benchmark、批量处理或新架构建设，都需要用户明确授权。
