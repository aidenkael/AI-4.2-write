# 2. 当前 Gate

**G4｜创作上下文与作者决策最小闭环：ACTIVE / G4-A。**

G4-A 当前产物：`06_工作区/G4A_最小创作合同_v0.1.md`（内容版本 v0.1.1）。

G4 不负责证明正文质量；完整 Writer / Reader / Critic / Editor 不属于当前 Gate。

## 2.1 唯一目标

证明系统能够把：

`Author Intent + Story State + 当前创作任务 + 读者目标 + 少量 BKP Hit`

编译成小而相关的 Context，并形成可用创作方向，同时保持：

- BKP 与原创 Canon 隔离；
- 作者掌握重大创作决定；
- 后台自动维护机械状态；
- 新会话不依赖旧聊天恢复作品状态。

## 2.2 作者控制边界

**作者控制 ≠ 作者审批。**

默认自动：Retrieval、Skill 路由、Context 编译、连续性检查、从已接受正文提取明确事实、机械状态结算。

需要作者显式确认：重大方向变化、与 Author Intent/Canon 的真实冲突、文本歧义、正文尚未成立的新解释或新剧情。

Story State authority：

- `accepted_text:<ref>`：明确文本事实，可自动结算；
- `author_decision:<id>`：重大创作决定；
- BKP / AI candidate / Context Package：不得成为 Canon authority。

# 4. G4 最小退出条件

G4 closeout 前至少证明：

1. 可丢弃原创沙盒中的 Author Intent / Story State 可文件化恢复；
2. BKP 与 Canon 严格分离；
3. Creation Brief 能驱动小而相关 Context；
4. Context 有来源、选择理由且可重建；
5. 人物 / 情节信息 / 读者体验等不同问题能做情境化 Cross-book Synthesis；
6. 方案真正有差异并说明依据、边界、风险；
7. 作者可接受、修改、拒绝；
8. 重大创作决定由作者确认；
9. 已接受正文中的明确事实可以自动机械结算，歧义/推断不得自动写回；
10. 作者偏离旧计划时，系统说明影响，不绑死作者；
11. 新会话/新 Agent 只读权威工件即可恢复状态；
12. 无真实阻塞不升级 Retrieval / RAG / KG；
13. closeout 同步长期文档和 provenance；
14. 作者明确验收后退出 G4。
