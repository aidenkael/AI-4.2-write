# AI-write 项目阶段门禁

> 当前 Gate、允许动作、退出条件和禁止范围的权威入口。更新时间：2026-08-13。

## 1. 当前 Gate

**单书蒸馏成品化：ACTIVE。**

G0–G4 已关闭。G5｜正文诊断与修订最小闭环：**PAUSED**，不作为当前主线。

## 2. 唯一目标

把现有 SourcePrepare + BookDistill 收成一个作者侧只有一次启动操作的单书流程：

`指定书名/book_id → SourcePrepare（如需）→ BookDistill → BKP Finalize → Retrieval 可发现 → 简短报告`

作者不需要理解内部命令、Pass、Schema、逐章 evidence 或 Deep Dive 文件。

## 3. 内部蒸馏规则

- SourcePrepare 只做输入标准化，不算文学蒸馏；
- Base Scan：全书基础扫描；
- Discovery：至少两个互补观察 Pass——长篇运行/读者动力、Reader/Page Craft；
- BookProfile 只负责导航与分配专项预算；
- Deep Dive 为 0～N 次，按作品实际强项/疑点触发，不固定数量；
- Finalize 做总编辑式回源核证、去重、合并、补 scope/boundary/counterevidence/confidence，并封装 BKP；
- 长书允许按章节/分块执行，不要求整书一次塞入模型；
- 单书 BKP 最高默认到 Work-specific Pattern，不自动升级为普遍写作规则。

《一九八四》《三体》曾各跑 3 次专项 Deep Dive，只是验证流程，不构成固定生产规则。

## 4. 完成条件

当前 Gate 只有四个退出条件：

1. 存在一个明确的单书 Agent 入口，用户只需指定书名/book_id；
2. 入口能自动判断 SourcePrepare 是否已有 PASS，没有则运行，有 REVIEW/FAIL 则明确停止并报告；
3. Agent 能按 BookDistill 现有方法完成多 Pass、0～N Deep Dive、总编辑收敛和 BKP Finalize；
4. 用一部此前未蒸馏的新书真实跑通，最终 BKP 通过校验且 KnowledgeRetrieve 能发现。

不要求当前完成批量流水线、UI、跨书知识成熟度或正式写作。

## 5. 当前允许

- 复用/改造现有 SourcePrepare 与 BookDistill 脚本；
- 增加最小单书 orchestrator / runbook / 状态判断；
- 增加必要的失败报告与最小恢复能力；
- 调整 Agent 提示与执行顺序，使一次操作可跑完；
- 选一部尚未蒸馏的新书做最终真实验收。

## 6. 当前禁止

- 不继续 G5 正文诊断实验；
- 不要求作者评价测试小说；
- 不批量蒸馏全部素材；
- 不重新发明 BookDistill 理论，只为“看起来更完整”；
- 不冻结固定 Deep Dive 次数；
- 不升级 Retrieval/RAG/KG；
- 不开发 Writer、UI、大型数据库或多 Agent 平台；
- 不用单个失败案例直接扩张长期架构。

## 7. 作者交互

正常成功路径中，作者只需要启动一次并看最终结果。

只有以下情况允许中途询问：

- SourcePrepare `REVIEW/FAIL` 需要人工选源或补素材；
- 作品身份无法确定；
- 两个互斥的重大文学解释都会显著改变最终 BKP，且现有证据无法裁决。

普通 Deep Dive 选择、证据归并、重复项清理、BKP 封装均由后台完成。

## 8. Git 安全

无明确授权禁止：`reset / restore / clean / force push / rebase / merge`。

历史 local dirty / untracked / `stash@{0}` 先识别再处理；普通同步不建立无意义长期分支。

## 9. 防跑偏

> **当前不是继续研究“AI 怎么写小说”，而是先把“AI 怎么把一本小说蒸馏成可长期调用的知识资产”做成简单可靠的成品。**
