# AI-write 项目阶段门禁

> 用途：约束跨会话、跨 Agent 的执行顺序，防止对话变长后偏离已确认路线。  
> 本文件只记录“当前阶段允许做什么、完成条件是什么、下一阶段什么时候才能开始”。  
> 若本文件与单次 Agent 临时建议冲突，以用户最新明确确认 + 本文件当前门禁为准；不得由 Agent 自行跳阶段。  
> 首次建立：2026-08-10；最近重大更新：2026-08-11。

## 一、执行前必读顺序

任何进入仓库的新 Agent / Controller，在开始实质工作前必须按顺序确认：

1. `00_项目控制/README_目录使用说明.md` —— 项目目标与目录权威说明；
2. `AGENTS.md` —— 长期执行、Git、本地保护、知识固化规则；
3. `AI-write_长期开发手册.md` —— 长期架构、开发路线、里子/面子与闭环规则；
4. `00_项目控制/当前工作索引.md` —— 当前状态入口；
5. `00_项目控制/项目推进记忆.md` —— 跨阶段关键决策；
6. 本文件 —— 当前允许动作与退出条件；
7. 本次任务涉及专项时，再读取对应 STATUS / 协议。

单次聊天摘要、Agent 自己的建议、旧计划不得覆盖以上长期文件和用户最新明确确认。

## 二、任务开始时必须先声明四件事

Agent 开始执行前，先用简短文字确认：

- 当前门禁阶段；
- 本次唯一主目标；
- 本次明确禁止触碰的范围；
- 本阶段退出条件中，本次准备完成哪一项。

如果无法从仓库确定这四项，先停止并汇报，不自行推断新路线。

## 五、后续 Gate 不预设为“直接正式创作”

旧文档曾把 G3 直接定义为真实作品工程最小闭环。该路线现在**不再自动成立**。

当前长期战略路线见根目录 `AI-write_长期开发手册.md`：

`能力层 GitHub 复查 → BKP/BookProfile → BookDistill vNext → 跨书知识与检索 → 创作核心后台 → 创作沙盒 → Production v1.0 → 正式长篇`

G2 退出时，再由用户根据当时成果定义下一 Gate。Agent 不得自行沿用旧 G3 名称或内容。

## 六、禁止“顺手扩展”

每次 Agent 任务只推进当前门禁中的一个明确子目标。

发现其他问题时：

- 可以记录；
- 可以提出下一步建议；
- 不得因为“顺手”“以后会用到”“架构更完整”直接扩大任务。

任何跨门禁动作、重大目录变化、新 Benchmark、批量处理或新架构建设，都需要用户明确授权。

## 七、阶段收口同步要求

每次 Gate closeout 或用户确认重大架构变化后，必须检查并同步：

1. `AI-write_长期开发手册.md`（含 AUTO 当前状态/下一步/风险）；
2. `00_项目控制/当前工作索引.md`；
3. `00_项目控制/项目推进记忆.md`；
4. 本文件；
5. `AGENTS.md`（仅长期规则变化时）；
6. 相关 STATUS / provenance。

然后 commit、报告 SHA；**没有用户明确确认，不自动切下一 Gate。**
