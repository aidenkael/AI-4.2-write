## 3.1 G4 唯一核心目标

证明 AI-write 可以在**不依赖聊天记忆、不把整个项目/全部 BKP 塞给模型、不自动替作者做重大创作决定**的前提下，把：

```text
作者意图
+ 当前作品状态 / Canon
+ 当前创作焦点
+ 希望读者经历什么
+ 少量相关 BKP 知识
```

编译成一个小而相关、来源清楚的创作上下文，然后：

```text
提出 1～3 个真正有差异的可行方向
→ 说明依据 / 风险 / 冲突 / 边界
→ 作者选择 / 修改 / 全部拒绝
→ 只在作者确认后更新计划 / Story State
```

**G4 不负责证明正文已经写得好。** Writer、Reader/Critic/Editor 的完整生产闭环不属于当前 Gate。

## 3.2 G4 的五种概念工件

G4 当前只验证：

1. **Author Intent**：作品方向、作者当前最在意/不想要的东西、Current Focus；
2. **Story State / Canon**：原创作品权威事实与当前状态；
3. **Creation Brief**：当前创作问题、人物欲望/阻力、读者目标、硬约束与自由空间；
4. **Context Package**：从权威状态和少量 BKP Hit 派生的小而相关上下文；
5. **Decision Record / State Diff**：作者确认后的决策理由和状态变化。

核心边界：**BKP / Book Knowledge 是参考知识；Canon / Story State 是原创作品事实。两者不得混写。**

# 四、G4 Borrow-first 分工

不选项目“总冠军”，不把成熟项目整套照搬。

- **InkOS**：G4 主骨架参照——Author Intent、Current Focus、Context Compiler、分支推演、确认前不污染 Canon、确认后状态治理；
- **AI-Novel-Writing-Assistant**：书/卷/章/场景任务层次、Reader Experience Contract、任务合同与状态回灌思想；
- **graphify-novel + NovelForge**：Story Bible / Canon、source of truth 与派生层分离、跨章状态、结构化资产；
- **ani-book-skill**：人可读权威工件、确定性校验、派生索引可重建、作者确认后写入长期事实；
- **creative-writing-skills**：Muse、多方案探索、后台专业角色隐藏路由；
- **Apodictic**：决策诊断 Firewall、风险与解决方向，不替作者写死；
- **oh-story**：中文长篇期待/回报、压力/换气、章节推进、关系/信息/情绪净变化与追读动力。

只有成熟上游没有解决的剩余缺口，才进入 AI-write 自研。

# 六、G4 最小退出条件

只有以下 14 项全部满足，且作者明确验收，才允许退出 G4：

1. 有可丢弃原创沙盒；Author Intent、Current Focus、最小 Story State 文件化保存，不依赖聊天记忆；
2. Canon / Story State 与 BKP 参考知识严格分离；
3. Creation Brief 能触发 Context Compiler，从项目状态和 KnowledgeRetrieve 中只选少量相关信息；
4. Context Package 能说明信息来源和选择理由，不需要全量塞入项目/BKP；
5. 至少对“偏人物 / 偏情节信息 / 偏读者体验”等不同创作问题验证情境化 Cross-book Synthesis；
6. 每次输出 1～3 个真正有差异的方向，不是同义改写；
7. 每个方向说明为什么适合当前作品、用了哪些参考知识、适用边界、主要风险/代价；
8. 作者可以选择 / 修改 / 全部拒绝，AI 不把多数意见或参考作品经验当规则强推；
9. 作者确认前 Canon / Story State 不发生正式写入；确认后有明确 State Diff / Decision Record；
10. 作者偏离旧计划时，系统先说明影响，再按作者确认更新计划/状态；
11. 新会话 / 新 Agent 只读权威工件即可恢复当前作品状态和最近一次重大决定；
12. 不修改 KnowledgeRetrieve、不升级 RAG/KG，除非真实验证出现阻塞性检索问题；
13. closeout 时同步项目控制文档、长期手册和 provenance；
14. 作者明确验收后才能退出 G4。
