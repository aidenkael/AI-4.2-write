## 1. 项目最终目标

AI-write 的目标不是“自动替作者生成一本小说”，也不是“把 GitHub 小说项目都装进一个仓库”。

目标是建立一套能长期辅助**不同题材、不同风格长篇小说**的 AI 创作工作台：

```text
参考与研究
→ 作品构思
→ 故事规划
→ 场景 / 章节创作
→ 审阅与诊断
→ 修订
→ 状态回写
→ 下一轮创作
```

作者层尽量简单：

`参考/研究 → 构思 → 规划 → 写 → 审阅 → 修改`

后台承担：

`Book Knowledge + Canon/Memory + Retrieval + Context Compiler + Planning + Writer + Reader/Critic/Editor + Continuity + Controller`

作者负责：作品方向、人物取舍、审美判断、重大创作决定。系统负责：资料、记忆、检索、方案推演、诊断、连续性、状态同步和技术路由。

## 2. 长期开发原则

### 2.1 Borrow-first

默认顺序：

`发现真实问题 → 查能力地图 / 成熟上游 → 最小真实测试 → 能借就借 → 只补剩余缺口`

不要因为“必须原创”而重复造轮子。

AI-write 自研重点收缩到：

- 协议；
- 路由与胶水；
- Book Knowledge Package（BKP）；
- BookProfile / 蒸馏预算逻辑；
- 中文长篇适配；
- 作者控制；
- 必要的状态接口。

Writer、Critic、Reader、Planner、Canon、Memory、Continuity、RAG/KG、Story Bible 等若已有成熟实现，先借/改。

许可证类型不作为当前私人研究阶段的技术淘汰标准；实际复制/修改仍保留来源、上游 commit/tag、LICENSE 与改动范围，未来公开/商用/服务化/分发时重新审计。

### 2.2 案例只负责暴露问题，不负责决定架构

单个章节、单个技巧、单次漏检不能直接升级成长期 Schema / Skill 分类。

正确路径：

`案例暴露问题 → 放回成熟作者完整能力地图 → 检查成熟上游 → 少量跨作品验证 → 只补真正的系统缺口`

### 2.3 真实任务优先，Benchmark 不是主项目

普通能力默认轻量验证；只有“长期核心规则 + 证据矛盾 + 固化错误代价高”时才升级严格 Benchmark。

B02 / B09 的方法学经验保留，但不复制成每个能力都要跑的大型研究流程。

### 2.4 作者不是机器

系统不能要求作者手动挑十几个 Skill、维护几十份状态表、或者为了系统一致性牺牲创作灵感。

作者偏离计划时：

`系统识别影响 → 说明后果 → 作者确认 → 更新计划 / Canon / Story State`

正式创作阶段默认阶段性冻结核心 Skill / 工作流，在卷末、阶段末或自然停顿点统一升级，保护创作连续性。

## 3. 参考书知识与原创作品状态必须严格分离

- **BKP / Book Knowledge**：参考作品中蒸馏出的知识资产；
- **Canon / Story State**：自己正在创作作品中的事实、人物、关系、时间、伏笔与状态。

参考书的 Pattern 不能污染自己小说的 Canon；自己小说的事实也不能被当成参考书知识。

结构化 Canon / BKP 是权威资产；向量、图谱、索引等默认视为可重建派生层。

---

## 4. 原著蒸馏的正确目标

BookDistill 的目标不是完成预设维度或制造整齐总结，而是：

> **尽可能发现并保存成熟作者真正会认为“值得学习、值得记住、未来创作可能重新调用”的作品精华。**

允许的发现跨尺度存在：

- 宏观：故事引擎、结构、世界、长线承诺与回收；
- 中观：场景组合、关系变化、节奏换挡、信息与情绪推进；
- 微观：一句话、一个动作、一个称呼、一个省略、潜台词、感官、幽默、欲望、留白；
- 读者体验：好奇、期待、压迫、放松、惊讶、审美、流畅感等连续变化；
- 人物因果；
- 跨场景/跨章节累积效果；
- **重要但暂时无法命名的创作智慧。**

预设维度是观察工具，不是知识边界。

## 5. BookDistill / BKP 当前成熟边界

### 5.1 evidence-first 地基继续保留

已验证并继续保留：

- SourcePrepare PASS 输入；
- 原著来源 snapshot / fingerprint；
- Evidence 可追溯到章节 / 行号；
- Fact / Inference / Observation / Pattern / Boundary 等边界；
- confidence；
- counterevidence / boundary；
- 不大量复制原文；
- 单书不能自行证明普遍写作规律。

### 5.2 BookDistill 不再承担“单枪匹马发现全部精华”

2026-08-12 G3 closeout 前正式修正为：

```text
原著
│
├─ 默认镜头 A：长篇运行 / 读者动力
│  └─ 优先借 oh-story + AI-Novel
│
├─ 默认镜头 B：Reader / Page Craft
│  └─ 优先借 creative-writing-skills
│
├─ 必要时 Developmental Deep Dive
│  └─ 优先借 Apodictic
│
└─ BookDistill 总编辑
   └─ 回源核证 → 区分 Observation/Inference → 去重 → 找组合效果
      → 补 Scope/Boundary/Counterevidence/Confidence → 必要再深挖 → BKP
```

关键纪律：

- 每个重要观察镜头可以直接读原著；不能只消费上一层摘要；
- 允许一条 Observation 由不相邻句子、场景、章节共同支撑；
- 允许保存“重要但暂时难以命名”的 Observation / Inference；
- Discovery 可以宽，最终 BKP 必须克制；
- 不新增几十个永久固定 taxonomy；
- 不因为猫、桂花糕等单案例新增硬编码规则。

### 5.3 BookProfile 只是导航和预算工具

BookProfile 不能在读书前决定“这本书只值得蒸馏哪几项”。

正确顺序：

`基础全书观察 → BookProfile → 明确强项 / 潜在强项 / 普通项 / 不确定项 → 1～N 次专项 Deep Dive → Profile 修正`

必须允许“多维都优秀”的书增加蒸馏预算。

### 5.4 一本书蒸馏次数不固定

目标是一本书处理完成后，大部分未来有价值的知识已进入 BKP；正式写作通常只检索，不临时重蒸馏整本原著。

未来系统出现新的重要观察能力时，允许旧书做“系统升级式再蒸馏”。

## 6. BKP 的认识论边界

BKP 是参考书的长期知识资产，不是写作规则列表。

当前知识成熟度原则：

`Source Evidence → Observation / Inference → Work-specific Pattern → Cross-book Pattern → Creation-tested Heuristic → Production Rule`

关键约束：

- 单本 BKP 内最高默认到 Work-specific Pattern；
- 跨书重复只增加支持度，不自动升级成 Production Rule；
- Production Rule 应非常少；
- 无法可靠抽象但有价值的发现可以长期保留为 Observation / Inference；
- Scope / Boundary / Counterevidence / Confidence 必须尽可能保留；
- 正式写作阶段默认检索少量相关知识，不把整个 BKP 塞给 Writer。

## 8. 成熟作者完整能力地图：六个大区

2026-08-12 完整能力审查确认，不再扩成几十个固定技巧分类：

1. **作品方向与判断**：读者、承诺、主题、题材、审美目标、作品究竟想成为什么；
2. **故事运行能力**：结构、人物、关系、世界、信息、悬念、兑现、长篇动力、章节与场景；
3. **读者与文本效果**：情绪、注意力、期待、欲望、幽默、恐惧、审美、连续体验、微观→宏观效果链；
4. **页面写作能力**：语言、声音、视角、心理距离、对白、潜台词、感官、动作、细节、意象、留白、节奏；
5. **判断与修订能力**：Reader Sim、Critic、Editor、Developmental Editing、为什么有效 / 为什么失效；
6. **长期知识与创作运行能力**：学习参考作品、Canon、检索、上下文编译、作者意图、写后回灌、长期成长。

永久开放入口：**重要，但目前无法命名。**

## 9. 长期核心上游参照

### AI-Novel-Writing-Assistant

主要借鉴：完整小说工作台、拆书→知识/RAG→规划/续写/正文、写法资产、Reader Experience Contract、卷/章/场景生产链、审校修复、状态回灌、运行时恢复。

不整体照搬：其产品更偏“帮助新手自动完成整本书”，而 AI-write 更强调作者重大决策权。

### oh-story

主要借鉴：中文网文拆解、剧情单元、情绪模块、节奏、期待/回报、长篇追踪、拆书资产回流卷纲/细纲/正文、去 AI 味。

### creative-writing-skills

主要借鉴：Muse、Writer、Critic、Editor、Reader Sim、Character Sim、Outliner、Continuity、Writing Principles、Page Craft、Story Memory。

核心产品思想：作者面对 Muse / 创作问题，后台专业角色自动路由，不要求作者操作十几个 Skill。

### Apodictic

主要借鉴：Developmental Editing、Reader Experience、Character Architecture、Reveal Economy、Scene Turn、Emotional Craft、POV/Voice、Decision Pressure 等诊断镜头。

关键原则：诊断问题和解决方案类别，但不强行替作者写具体内容。

### InkOS

主要借鉴：author_intent、current_focus、Context Compiler、未来分支推演、确认后再写回、Canon / 状态治理、写作→审计→修订→状态回灌。

### graphify-novel / NovelForge / ani-book 等

继续作为 Canon / Story Bible / KG / 结构化资产 / evidence-first / 可重建索引等能力参照；真实需求出现时触发复查，不提前全量整合。

**未实现，正式留给 Phase E。**

`作者意图 + 当前 Canon/人物/关系/章节状态 + 希望读者经历什么 + 少量 BKP Hit`

**未实现，正式留给 Phase E。**

## 15. 一句话总纲

> **AI-write 的中心不是“知识越来越多”或“系统越来越严谨”，而是：从优秀作品中学到真正有价值的创作智慧，在当前原创作品的作者意图和故事状态下重新创造，用真实读者体验检验效果，并持续写回长篇状态；工程稳定保证下限，人物生命力、读者体验与审美能力决定上限。**
